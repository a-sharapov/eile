# Видение

**Eile** — CMS, которая повторяет суть MODX Evolution на современном стеке: просто, быстро, без лишнего.
Bun, SQLite и Svelte 5, поставка одним исполняемым файлом.

Название: по-немецки «спешка». «Eile mit Weile» — поспешай не торопясь: сайт отдаётся мгновенно, а
работа в менеджере спокойная.

## Почему Evo

Evo любили за простоту:

- **Дерево страниц — центр мира.** Сайт — это дерево, и менеджер показывает именно его.
- **Правка в браузере видна сразу.** Поменял чанк — он на сайте, без сборки и деплоя.
- **Быстро «из коробки».** Готовый HTML лежит в кэше, PHP почти не работает.
- **Установил и работает.** Залил файлы на хостинг — сайт готов.
- **Мало сущностей.** Шаблон, чанк, сниппет, TV, плагин — и этого хватает на большинство сайтов.

## Принципы

1. **Один файл — один сайт.** Бинарник плюс файл базы SQLite. Бэкап — копия файла. Это современный эквивалент
   «залил по FTP».
2. **Быстро по умолчанию.** Публичная страница — готовый HTML из кэша и ноль JS на клиенте. Скрипты появляются
   только там, где компонент явно попросил гидрацию.
3. **Правка видна сразу.** Шаблоны и компоненты хранятся в базе и компилируются при сохранении, без сборки.
4. **Svelte вместо зоопарка тегов.** `{{chunk}}`, `[[snippet]]`, `[*tv*]`, `[~id~]` заменяются обычными
   импортами и выражениями Svelte.
5. **Чистая предметная модель.** DDD с первого коммита: язык предметной области в коде, контексты с явными
   границами, правила зависимостей проверяются тестом.
6. **Меньше, но лучше.** Берём суть Evo, а не его легаси. Совместимость с PHP-кодом не цель.

## Чего не делаем

- Headless-only CMS: публичный сайт — главный продукт, API — дополнение.
- Поддержку разных СУБД: только SQLite (см. [ADR 0001](adr/0001-bun-sqlite-single-binary.md)).
- Выполнение PHP-сниппетов Evo. Перенос сайтов — через импорт с конвертацией (см. [roadmap](roadmap.md)).
