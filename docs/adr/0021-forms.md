# 0021. Формы как в eForm: HTML5-разметка, тег `[#Form:имя]`, заявки

- Статус: принято
- Дата: 2026-10-30

## Контекст

Почти каждому сайту нужны формы: обратный звонок, заявка, вопрос. В Evo их делают двумя способами.

- **eForm.** Форма — обычный HTML-чанк, правило поля пишется рядом с ним атрибутом, отчёт и «спасибо» — свои
  чанки.
- **FormLister.** Правила — массивы в вызове сниппета, плюс контроллеры. Защита от повтора `protectSubmit` и
  лимит `submitLimit` держатся на сессии PHP (`assets/snippets/FormLister/lib/SubmitProtection.php`).

Владелец сайта выбрал идеологию eForm и хочет визуальный редактор форм. Заявки должны храниться в базе,
приходить менеджерам (конверт в шапке, мини-дашборд) и уходить в Telegram и на почту (ADR 0020).

## Решение

**Форма — HTML5-разметка.** Правила поля — его атрибуты: `required`, `type` (email, tel, url, number, date…),
`pattern`, `min`/`max`/`step`, `minlength`/`maxlength`, варианты `<option>` и группы переключателей.

- Подпись поля — `data-label` у обёртки `[data-field]`, иначе `<label for>`, `aria-label`, `placeholder`.
- Свой текст ошибки — `data-message`; скрытое поле с `data-source` берёт значение из источника.
- Сервер читает разметку `HTMLRewriter` (синхронно, на строке) и проверяет заявку по тем же правилам, что и
  браузер. `pattern` компилируется с флагом `v`, как в HTML; неверный шаблон не проверяется — так же поступает
  браузер.
- Сущности в атрибутах `HTMLRewriter` отдаёт сырыми: их раскрываем сами, а при записи значений экранируем `&`
  и `<`.
- Ничего, кроме полей из разметки, в заявку не попадает.

**Редактор — блоками, как текст страницы.**
- Поле — блок с формой параметров; текст и неполевая разметка — текстовые блоки.
- Нетронутое поле сохраняется как было, правленое — в каноническом виде; ручная вёрстка не теряется.
- Разбор в менеджере — DOM браузера, сборка — чистая функция. Совпадение сборки с разбором сервера проверяет
  `tests/form-blocks.test.ts`.
- Справа — предпросмотр: сервер рисует несохранённую форму в песочнице.

**Вставка.**
- В тексте — тег модуля `[#Форма:имя]`: `[#Form:callback]`. Форма — данные, а не компонент, поэтому у неё свой
  синтаксис, общий для будущих модулей. В редакторе контента это блок «Форма» с выбором из списка; разбор
  менеджера и сайта совпадает (`tests/content-blocks.test.ts`).
- В шаблоне — `$core/Form`.
- Тег становится регионом вида `module` и рисуется на каждом запросе: свежая печать, метки UTM, Referer, флеш.
  Страница вокруг остаётся в кэше, события форм кэш не сбрасывают.
- Ссылки `[~id~]` внутри формы (политика в согласии) раскрываются в адрес страницы.

**Приём: `POST /_cms/forms/<имя>`** — только с того же сайта (`Origin`, `Sec-Fetch-Site`), тело не больше
64 КБ.
- **Без JS — Post/Redirect/Get.** Успех — 303 на страницу «Спасибо» или обратно с `?sent=имя`, F5 не отправит
  форму второй раз. Ошибка — 303 обратно и флеш-cookie (HttpOnly, две минуты): форма покажет введённое и
  ошибки у полей.
- **С JS** — скрипт улучшения (обычный JS в бинарнике, `/_cms/forms/enhance.<хэш>.js`):
  - отправляет JSON без перезагрузки и показывает ошибки у полей;
  - устаревшую печать молча меняет на свежую и отправляет снова;
  - хранит черновик в `localStorage` и стирает его только после успеха;
  - запоминает метки UTM первого касания;
  - шлёт событие `cms:form-sent`.

**Защита без капчи.**

| Средство           | Как работает                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Ловушка            | Невидимое поле; заполнено — успех без записи                                                                            |
| Печать             | `Bun.CSRF` с `sessionId` = форма и момент показа; срок — сутки, повтор той же печатью — тот же успех без второй записи  |
| Минимальное время  | Быстрее `minSeconds` (по умолчанию 3) — «подождите»                                                                     |
| Лимит              | Не больше пяти заявок с адреса за 10 минут на форму, окно фиксированное — без вечной блокировки                         |
| Повтор             | Та же заявка за 3 минуты — тот же успех                                                                                 |
| Спам по содержанию | Ссылки (если форма их не ждёт) и разметка. Заявка сохраняется со статусом «спам» без уведомления — ошибку фильтра видно |
| Скрытые поля       | Значения страницы, сайта и времени сервер подставляет сам — подменить их нельзя                                         |

**Заявка** — снимок значений с ключами и подписями (правка формы не ломает старые заявки).
- Также хранятся страница, Referer, метки UTM, IP (владелец решил хранить), браузер, статус («новая», «в
  работе», «готово», «спам») и заметка.
- Первое открытие менеджером делает её прочитанной.
- Удаляется по сроку формы, по умолчанию через 30 дней (152-ФЗ); заявки удалённых форм — через 30 дней.
- Уведомление уходит через `notify` в каналы формы или по маршруту из настроек: тема с `{form}` и `{имя поля}`,
  ответ на письмо — почте посетителя, ссылка — в карточку заявки.

**Права.** Формы собирает администратор (`forms.edit`), заявки разбирают все менеджеры (`inbox.read`).
Удалить заявку навсегда, вместе с файлами, может только администратор (`inbox.delete`): статус, заметку и
повторную отправку уведомления редактор меняет сам.

## Последствия

- Конверт в шапке опрашивает сводку раз в 30 секунд, пока вкладка видна.
- Секрет печатей — таблица этого сервера, в копию сайта не попадает; формы и заявки — попадают.
- Плагины могут подписаться на `forms.submission_received` — например, чтобы передать заявку в CRM.
- Условные поля, шаги и файлы — дополнение ниже.

## Дополнение 2026-10-31: условные поля, шаги, файлы

Форма остаётся разметкой HTML5, и всё новое — тоже атрибуты.

**Условное поле** — `data-show-if="поле=значение|значение"` у обёртки `[data-field]` (или `data-show-if="поле"` —
показать, когда поле заполнено или отмечено).
- Скрипт прячет обёртку и выключает её элементы: `required` скрытого не мешает, выключенное поле не уходит.
- Сервер проверяет то же (`isShown`): скрытое условием поле не проверяется и в заявку не идёт, даже если
  его прислали. Поле зависит от показа того поля, на которое ссылается; ссылка на поле, которого нет в форме,
  не скрывает — так же поступает скрипт.
- Без JS видны все поля, и сервер решает по присланным значениям.

**Шаги** — `<fieldset class="form-step" data-step="Название">`.
- Скрипт показывает один шаг, «Далее» проверяет поля шага, отправка — на последнем; ошибка сервера открывает
  шаг с первым неверным полем.
- Кнопки и счётчик («Шаг {n} из {m}») — на языке страницы: сервер кладёт их в атрибуты `<form>`.
- Без JS форма видна целиком. Сервер шагов не различает.

**Файлы** — `<input type="file">` с `accept`, `multiple` и `data-max-size` в мегабайтах.
- Предел — 10 МБ на файл по умолчанию, не больше 20; до 10 файлов в поле; тело заявки с файлами — до 50 МБ,
  без файлов — по-прежнему 64 КБ.
- Форма с файлом получает `enctype="multipart/form-data"`, скрипт шлёт её `FormData`.
- Тип проверяется по `accept`: `.pdf` — по имени, `image/*` — по началу типа, остальное — тип целиком.
- Файлы хранятся в базе (`forms_files`) рядом с заявкой и уходят вместе с ней. В копию сайта они попадают:
  это часть заявки.
- Скачать файл может только менеджер с правом на заявки — всегда как вложение,
  `application/octet-stream`, с `nosniff` и `sandbox`: файл посетителя не откроется страницей на адресе
  менеджера.
- В уведомлении — имена файлов и ссылка на заявку, вложений нет.
- Файлы спама не сохраняются; имена файлов фильтр спама не смотрит.

## Дополнение 2026-10-31: проверка перед релизом

- **Условие по файлу.** Для условий у поля-файла значения — имена приложенных файлов (`shownValues`):
  «показать, если приложили резюме» сервер решает так же, как скрипт.
- **Скрытые поля с источником на сервере** (страница, сайт, время) получают свои значения до проверки:
  присланное посетителем значение такого поля не решает ни условий, ни заявки.
- **Несколько значений** (`multiple`) — формат и шаблон проверяются у каждого, а не только у первого.
- **Тело заявки** читается только после того, как форма найдена и лимит частоты не превышен: несуществующая
  форма — 404, большой предел тела — только форме с полем-файлом, остальным — 64 КБ (413). Одновременно
  принимается не больше четырёх заявок с файлами, пятая получает 503 с `Retry-After`.
- **CSV.** Значение, которое начинается с `=`, `+`, `-`, `@` или табуляции, выгружается с апострофом
  впереди: Excel не примет его за формулу.
- **Конструктор.** Шаг без названия — конец шагов: поля ниже снова видны всегда. Enter в поле промежуточного
  шага — «Далее»; перед отправкой проверяется вся форма, неверное поле открывает свой шаг.

## Дополнение 2026-11-02: немецкий, письмо отправителю, cookie, вебхук

Для сайтов на немецком и заказов B2B, которые уходят дальше, в CRM.

**Немецкий.** Ошибки полей, тексты скрипта (кнопки и счётчик шагов, ловушка, сбои отправки) и тексты новой
формы по умолчанию (кнопка, «спасибо», тема уведомления) — на ru, en и de.
- Язык — страницы, иначе сайта; язык без своих текстов — английский, как и раньше.
- Тексты новой формы берутся по языку сайта при сохранении; раньше они были русскими на любом сайте.
- Набор компонентов на немецком сайте — английский набор, в котором подписи для посетителя немецкие.

**Письмо отправителю** — настройка формы `confirmation`: включено ли, поле с адресом (по умолчанию первое
`type=email`), тема и обычный текст с `{form}` и `{имя поля}`, как у темы уведомления.
- Уходит только за заявку, которая прошла печать, ловушку, проверку полей и фильтр спама.
- Адрес — один, без запятых, скобок, кавычек и пробелов. В подстановках нет управляющих символов и
  переключателей направления текста, в теме — переводов строки. HTML письма экранирует всё, а разметка в
  значениях и так делает заявку спамом.
- Не больше одного письма на адрес с одной формы за 10 минут, окно фиксированное: так форма не станет
  рассылкой на чужие адреса. Журнал — в памяти процесса, как лимит отправок с адреса; после перезапуска
  он начинается заново.
- Письмо идёт через очередь `notify` — почта из настроек уведомлений, те же повторы, своего транспорта нет.
  Почта не настроена — письма нет.
- Источник в очереди — `confirmation:<id>`: «Отправить ещё раз» у уведомлений письмо посетителю не повторяет.
  Недоставленное письмо (опечатка в адресе) — не сбой сайта, его видно в карточке заявки.
- Тема — как её написал владелец сайта, без названия сайта в конце; ответ на письмо уходит на адрес отправки.

**Скрытое поле `cookie:имя`** — cookie посетителя, например код партнёра.
- При показе формы значение cookie — в значении поля. При отправке сервер берёт cookie из запроса с заявкой:
  присланное значение поля не решает, как у источников страницы и сайта.
- Cookie самой CMS — `cms_…` (вход в менеджер, флеш формы и всё, что CMS заведёт под этой приставкой) и
  с приставками `__Host-`, `__Secure-` — в поле не берутся. Форму с таким источником сервер не сохранит
  (`forms.reserved_cookie`), а при показе и отправке такое имя даёт пустое значение: сеанс менеджера не
  утечёт в страницу и в заявку, которую читают все менеджеры.

**Вебхук** — каждая принятая заявка уходит JSON-ом с подписью на адрес формы; решение —
[ADR 0037](0037-form-webhooks.md).

**Событие `forms.submission_received`** несёт ещё `values` (имя поля → значение) и `spam`.
- Шина синхронная и живёт в памяти: события нигде не хранятся и не пишутся в журнал. Журнал сбоев смотрит
  только события пользователей менеджера и берёт из них номер пользователя, ошибка плагина пишется без события.
- Плагин и так работает в процессе сервера: значения в событии не дают ему нового доступа, но избавляют
  от чтения базы.

## Дополнение 2026-11-03: подписи значений скрытого поля

Скрытое поле с ключом (`?paket=planung`) получает подписи атрибутом
`data-labels="berater=KI-Küchenberater|planung=KI-Küchenberater + KI-Planung"` и дальше ведёт себя как список:
письмо, уведомление, заявка и CSV показывают подпись, вебхук — ключ в `values` и подпись в `labels`. Решение —
[ADR 0041](0041-hidden-field-labels.md).

## Дополнение 2026-11-03: доказательство работы

К ловушке, печати и минимальному времени добавилась задача для браузера без капчи и cookie: SHA-256 перебором, как ALTCHA,
без чужого сервиса. Решение — [ADR 0053](0053-proof-of-work-forms.md).

- Задача выдаётся с каждым показом формы, подписана вместе с печатью и формой; одноразовость даёт печать, записей на сервере
  нет.
- Скрипт улучшения решает её в воркере с первого касания формы, отправка ждёт решения; строка состояния — `role="status"`.
- Неверное или отсутствующее решение — отказ с новой задачей (скрипт решит её сам), в базу ничего. Браузер без JS
  (метка `_nojs` из `<noscript>`) проходит прежние проверки, и заявка сохраняется спамом с пометкой.
- Настройка формы `proof`: `off`, `light`, `standard`, `strong`. У новой формы — `standard`, у сохранённой раньше — `off`.

## Дополнение: ошибки у поля и в браузере (0.1.0, 2026-11-04)

- Подсказка поля (`.hint` в обёртке `[data-field]`) получает id и связана с полями обёртки через
  `aria-describedby` всегда, а не только после ошибки сервера: экранный диктор читает её вместе с полем. Свой
  id подсказки сохраняется (с префиксом формы), без него — `<форма>-hint-<номер обёртки>`.
- Со скриптом форма проверяется им самим (`novalidate`): ошибки required, pattern и типа встают у поля так
  же, как их рисует сервер, — текст из `data-message` поля или обёртки, иначе сообщение браузера; фокус — на
  первом неверном поле, его шаг открывается. Исправленное поле теряет ошибку сразу. Без скрипта остаётся
  проверка браузера со всплывающими подсказками.
- `data-min="today"` у поля с датой — «не раньше сегодня»: скрипт ставит `min` по часам посетителя (страница
  в кэше), сервер проверяет при каждой отправке с запасом в день к западу от UTC (`MIN_TODAY`). У других
  типов атрибут ничего не значит.
