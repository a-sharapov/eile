# 0018. HTML редактора: чистка, инертные типы, песочница

- Статус: принято
- Дата: 2026-10-30

## Контекст

Аудит безопасности показал: сайт и менеджер живут на одном адресе, поэтому скрипт, который редактор
сохранил в тексте страницы (даже в черновике), выполняется у администратора при просмотре или
предпросмотре — с его cookie и его правами. Скрипт создавал администратора и переписывал шаблон, а код
шаблона выполняется на сервере. Страницы-файлы (ADR 0017) добавили к этому SVG, XML, XHTML и JS с корня
сайта, а JS по адресу `/sw.js` — ещё и service worker на весь адрес, включая менеджер.

## Решение

- **Право на код — граница доверия.** Кто правит элементы (`design.edit`), и так выполняет код на
  сервере: его HTML не трогаем. У остальных менеджер чистит HTML при сохранении — текст страницы, анонс
  и поля с оформлением — по белому списку (`sanitizeHtml`, HTMLRewriter Bun): без скриптов,
  обработчиков `on*`, `javascript:`/`data:` в адресах (сущности раскодируются до проверки), фреймов, SVG
  и MathML, стилей, комментариев (кроме `<!--noindex-->`) и меток CMS (регионы, острова).
  Сменил тип файла на HTML — чистится и прежний текст.
- **Инертные типы.** Редактор выбирает только типы, которые браузер не исполняет: HTML (с чисткой),
  текст, CSS, Markdown, CSV, календарь, JSON. SVG, XML, ленты, XHTML, JS и другие — администратор;
  текст таких файлов редактор видит, но не правит (`manager.type_not_allowed`, 403).
- **Песочница.** Предпросмотр отдаётся с `Content-Security-Policy: sandbox allow-scripts allow-popups
  allow-forms` — без `allow-same-origin` скрипт черновика не получает ни cookie менеджера, ни его API.
  Страница-файл — с `default-src 'none'; style-src 'unsafe-inline'; sandbox`, как SVG медиатеки.
- **Service worker** со страниц сайта не регистрируется: запрос с `Service-Worker: script` получает 404.
- **Менеджер** в схеме визуального редактора тоже отбрасывает исполняемые адреса ссылок и картинок.
- **Служебные имена.** Чистка снимает `id` и `name` с приставкой `eile-`/`cms-` (`_RESERVED`): HTML
  редактора не подменит элемент, который ищут скрипты CMS. Настройки полосы правки к тому же лежат в
  атрибуте самого скрипта (`data-eile-bar`), а не в отдельном элементе страницы, и скрипт пропускает только
  цвет вида `#rrggbb` и адреса `/manager/…`.
- **Заголовки страниц сайта.** HTML-страницы отдаются с `X-Frame-Options: SAMEORIGIN` и
  `Content-Security-Policy: frame-ancestors 'self'` (форму на сайте не накроют чужим фреймом) и
  `Referrer-Policy: strict-origin-when-cross-origin`. Встроенный HTTPS добавляет
  `Strict-Transport-Security: max-age=31536000`.

## Последствия

- Редактор не вставит iframe (видео) и `style` — это может администратор или компонент.
- Чистка срабатывает при сохранении: текст, сохранённый до этого решения, остаётся как был.
- Отдельный адрес для менеджера закрыл бы и другие пути (самый надёжный вариант) — это следующий шаг.
