# 0008. Острова: гидрация отдельных компонентов

- Статус: принято
- Дата: 2026-10-29

## Контекст

Страница CMS по умолчанию — HTML без JS. Но корзине, форме или калькулятору нужна интерактивность.
Гидрировать всю страницу (как SvelteKit) — значит отдать JS там, где он не нужен.

## Решение

- `<Island name="Counter" props={…} />` из `$core/Island` отмечает место, как `Uncached`. Во второй
  фазе компонент рендерится на сервере **с маркерами гидрации** и заворачивается в
  `<cms-island data-module data-props style="display:contents">`.
- Клиентский модуль острова компилируется во время работы (`generate: 'client'`, `css: 'external'`) и
  отдаётся браузеру как ES-модуль `/_cms/islands/Name.<hash>.js`. Бандлер не нужен: импорты
  переписываются на URL. Компоненты, которые импортирует остров, становятся такими же модулями.
- Рантайм Svelte для браузера собирается `Bun.build` со `splitting`: `svelte` и `svelte/internal/client`
  делят общий чанк, иначе у них было бы два экземпляра состояния. URL рантайма содержит хэш версии. В
  бинарнике рантайм собран заранее (`scripts/build.ts`), в разработке собирается при первом острове.
- Один загрузчик на страницу: `import()` модуля каждого острова и `hydrate(…, { target, props })`.
- Модули островов и рантайма отдаются с `immutable`: в пути есть хэш.
- Остров не может импортировать `$core`: он работает в браузере, а данные сервера получает через props.

## Последствия

- JS появляется только на страницах с островами и только для них.
- Стили острова приходят с серверным HTML: хэш классов совпадает, потому что совпадает имя файла.
- Props острова идут через JSON в атрибуте и должны сериализоваться.
- Острова внутри регионов и других островов не поддерживаются.
