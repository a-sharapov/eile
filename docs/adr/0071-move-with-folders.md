# 0071. Переезд со связанными папками

- Статус: принято
- Дата: 2026-11-09

## Контекст

Связанные папки ([ADR 0065](0065-linked-folders.md), [ADR 0068](0068-static-site-folder.md)) не входят в копию
базы. Переезд gabriel.by на сервер требовал руками скопировать `assets/` (2 ГБ) и `razbor/` рядом с базой
службы, а у живой базы разработчика папка лежала вне её каталога и была записана абсолютным путём: после
переноса он вёл бы в никуда. `cms service install --from` переносил только базу.

## Решение

- **`cms backup <папка> --folders`** — копия для переезда: в папке `site.db` (согласованная, как у `cms backup`) и
  связанные папки рядом с ней. Файлы копируются с прежним временем изменения (reflink на btrfs и xfs — место не
  тратится), запись папки в копии — от каталога базы: прежний относительный путь (`assets`) или, для папки вне
  каталога, имя по приставке (`media/old` → `media-old`). Папка копии — новая или пустая.
- **`cms restore <папка>`** — база из `site.db`, связанные папки — рядом с восстановленной базой.
- **`cms service install --from <папка | база>`** — база и её папки в каталог службы; владелец скопированного —
  как у каталога. С файлом живой базы папки тоже переезжают.
- Папку, что уже лежит на новом месте, ни одна команда не перезаписывает: база ведёт на неё, отчёт об этом
  говорит.
- Общий шаг — `carryFolders()` в `src/workspace/media.ts`: копия и перепривязка через `linkMedia` (сверка по
  размеру и времени изменения — без чтения файлов).

## Последствия

- Переезд сайта со старым `assets/` — две команды: `cms backup move/ --folders` и
  `cms service install --domain … --from move/`.
- Без `--folders` копия, как прежде, — один файл; команда напоминает о папках.
