# 0037. Вебхук формы: заявка JSON-ом с подписью, повторы из очереди

- Статус: принято
- Дата: 2026-11-02

## Контекст

Заказ с формы часто нужен не только в почте менеджера, но и во внешнем сервисе: CRM, учёт подписок,
таблица. ADR 0021 обещал, что для этого хватит плагина на `forms.submission_received`, но событие несло
только номер заявки и имя формы. Значения плагин мог достать только из базы, в обход контекста форм.

Владельцу сайта нужно: указать адрес, получить секрет, видеть у заявки, дошла ли она, — без кода.

## Решение

**Вебхук — настройка формы**: `webhook.url` и `webhook.secret`.
- Адрес — только `https://`; `http://` — только `localhost` и `127.0.0.1`, для приёмника на той же машине и
  тестов. Заявку с личными данными открытым текстом по сети не шлём.
- Секрет выдаёт сервер: 32 случайных байта в hex, вместе с первым адресом и по просьбе `renew`. Снаружи его
  задать нельзя, без адреса он сохраняется. Ключ HMAC — сама эта строка.
- Секрет живёт в настройках формы и уходит с ней в копию сайта: восстановленный сайт подписывает тем же
  ключом. В папку элементов (`cms elements pull`) и в ответы инструментов агента секрет не попадает: папку
  кладут в git, разговор с моделью — не место для ключей.

**Запрос.** На каждую принятую заявку — `POST` с JSON:
`{ form, submissionId, receivedAt, values: { имя: значение }, files: [имена], page: { id, url } }`.
- Файлов в теле нет — только имена; сами файлы менеджер скачивает из карточки.
- Заголовок `X-Eile-Signature: sha256=<hex>` — HMAC-SHA256 тела секретом формы (`Bun.CryptoHasher`).
  Приёмник считает подпись по сырому телу и сравнивает за постоянное время.
- Срок ответа — 10 секунд. Редирект не выполняется: это ответ приёмника, а не новый адрес для заявки.
- Спам, ловушка, устаревшая печать и ошибки полей на вебхук не уходят — как и уведомления.

**Повторы — своей очередью форм, по образцу очереди `notify`.**
- Таблица `forms_webhooks`: строка на заявку — статус, попытки, срок следующей, последняя ошибка, когда
  доставлено. Фон — `Bun.cron` раз в минуту и сразу после заявки; после перезапуска очередь продолжается.
- Тело собирается из заявки на каждую попытку, адрес и секрет берутся у формы на момент попытки: личные
  данные не хранятся второй раз, а поправленный адрес сразу получит повтор. Удалили заявку — доставка
  удаляется с ней.
- 2xx — доставлено. 5xx, 408, 425, 429, сеть и срок ответа — повтор через минуту, 5 и 30 минут, 2 часа:
  пять попыток. Редирект и прочие 4xx — отказ сразу: тот же запрос ничего не изменит.
- Попытки кончились — сбой `forms.webhook_failed` в журнал и в каналы сбоев. В карточке заявки видно, что
  с доставкой, и есть «Отправить ещё раз».
- Текст ошибки сети — без адреса: в адресе бывает пароль, а ошибка уходит в журнал и в Telegram.

**Почему не через `notify`.** Очередь уведомлений шлёт `Message` в настроенные каналы, а её таблица — этого
сервера и в копию сайта не входит. Доставка вебхука — часть заявки: она идёт в копию вместе с заявкой и
удаляется вместе с ней. Расписание повторов то же, что у уведомлений.

**Почему не только плагин.** Плагин — код: его пишут, проверяют и обновляют. Адрес и секрет владелец сайта
вписывает сам, а итог виден у каждой заявки. Плагину значения тоже доступны: событие
`forms.submission_received` теперь несёт `values` и `spam` (дополнение к ADR 0021).

## Последствия

- Вебхук настраивают в форме (вкладка «Интеграции»), через API менеджера (`PUT /forms/:name`) и
  инструмент агента `save_form`. Повтор вручную — `POST /inbox/:id/webhook`.
- Сохранить вебхук может только тот, кто правит формы (`forms.edit`); агент, читавший заявки, — нет.
- Доставка по одной: медленный приёмник задерживает остальных до 10 секунд на заявку.
