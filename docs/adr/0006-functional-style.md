# 0006. Функциональный стиль: `pipe`, фабрики `define*`, агрегаты как данные

- Статус: принято
- Дата: 2026-10-29

## Контекст

Каркас был написан на классах: агрегаты с методами, сервисы-команды, адаптеры-классы. Команда пишет на TS в
функциональном стиле и хочет, чтобы код CMS читался так же.

## Решение

- Цепочки шагов — `pipe`, накопление — `reduce`, ветвление — выражения и таблицы, без early return.
- Классов нет. Агрегат — неизменяемые данные, переход — чистая функция, которая возвращает
  `Changed<State, Event>`.
- Сервисы, репозитории и адаптеры — фабрики `define*(deps)`, которые возвращают объект операций.
- Ошибки домена — `fail(code, message)` внутри выражения.
- Форматирование и линт — Biome.

Подробные правила — [code-style.md](../code-style.md).

## Последствия

- Доменная логика тестируется без моков: на вход состояние, на выходе новое состояние и события.
- Зависимости видны в сигнатуре фабрики, а тесты подставляют свои порты.
- DDD-слои и правила зависимостей ([ADR 0002](0002-ddd-modular-monolith.md)) не меняются, меняется только
  форма кода внутри слоёв.
- `pipe` типизирован перегрузками по числу шагов: tsc выводит тип каждого стыка, в том числе после шага с
  Promise, и асинхронный сценарий пишется как `Promise.resolve(x).then(pipe(…))` (дополнено 2026-10-31;
  раньше шаги были `any → any`, а типы задавались явно, `pipe<In, Out>`).
