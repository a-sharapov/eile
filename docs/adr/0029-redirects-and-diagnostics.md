# 0029. Редиректы в менеджере и диагностика сайта

- Статус: принято
- Дата: 2026-10-31

## Контекст

Сайт уже сам отвечает 301 со старых адресов страниц: смена алиаса или перенос не ломают ссылки
(`content_old_paths`). Остальные переадресации — со старого сайта при переезде, с адреса из листовки,
с удалённого раздела — делались плагином с хуком `notFound`. Это код, а владелец сайта хочет таблицу.

Второе желание — понять, всё ли с сайтом в порядке, не обходя его руками: битые ссылки, страницы без
описания, картинки без `alt`, формы, заявки которых никуда не уходят. В Evo для этого ставили сторонние
модули.

## Решение

### Редиректы — контекст `redirects`

**Правило** — данные: `from`, `to`, код 301 или 302, заметка, счётчик переходов и время последнего.
- `from` — точный путь сайта или раздел со звёздочкой (`/blog/*`). Звёздочка в `to` получает остаток
  адреса: `/blog/*` → `/news/*` переносит `/blog/2024/post` в `/news/2024/post`.
- `to` — путь (можно с query), полный URL или страница `[~id~]`. Цель-страница идёт за ней после смены
  алиаса и переноса; снятая с публикации страница выключает правило — посетитель получает обычный 404, а
  не переадресацию в 404.
- Query запроса сохраняется, в том числе у внешней цели, и склеивается с query самой цели.
- Адреса менеджера, служебных файлов и медиатеки (`/manager`, `/_cms`, `/media`) правилом не занять.

**Порядок ответа.** Живая страница → правило → прежний адрес страницы → плагин `notFound` → страница 404.
- Страница важнее правила. Ошибка в правиле не закроет живую страницу, а дерево страниц и кэш не
  смотрят в правила на каждом запросе. Если правило совпадает со страницей, оно сохраняется с
  предупреждением и заработает, когда страницы не станет.
- Правило важнее прежнего адреса и плагина: это явное решение человека, а не автоматика.
- 404 не кэшируются, поэтому новое правило работает с первого же запроса — сбрасывать кэш не нужно.

**Цепочки и петли не сохраняются.** Отказ получает правило, которое:
- ведёт само на себя или в свой раздел;
- ведёт на адрес, который сам переадресуется — другим правилом или как прежний адрес страницы;
- принимает переадресацию от другого правила.

Каждый лишний переход — лишний запрос посетителю и поисковику, петля — ошибка в браузере.

**CSV.** Выгрузка — запятая и кавычки по RFC 4180. Загрузка принимает запятую или точку с запятой (так
сохраняет русский Excel) и обновляет правило с тем же `from`. Строки с ошибкой пропускаются; в отчёте —
номер строки и причина.

**Менеджер:** «Настройки → Редиректы».
- Правила — таблица с поиском и правкой в строке.
- Ниже — прежние адреса страниц только для чтения; ненужный адрес можно забыть.
- Права — `site.edit`, как у остальных настроек.

### Диагностика — контекст `diagnostics`

**Отчёт** — список находок, сгруппированных по разделам: ссылки, страницы, медиатека, настройки,
сервер.
- Находка: важность (`error`, `warning`, `info`), текст и почему это важно.
- Затронутые страницы и файлы — первые сто, плюс общее число.
- Ссылка «Исправить» — адрес в менеджере.
- Тексты находок по-русски приходят с сервера: проверке другого модуля не нужны правки в менеджере.

**Расширение.** `diagnostics.register({ id, run })` добавляет проверку; тот же id её заменяет.
- Упавшая проверка — тоже находка (`check.failed.<id>`), а не 500.
- Так подключаются проверки автокопий, HTTPS и обновлений.

**Встроенные проверки** читают один снимок сайта (`SiteFacts`), который собирает корень приложения
(`src/site-facts.ts`): контексты друг о друге не знают.
- **Ссылки:** `[~id~]` и `href`/`src` на путь сайта — в никуда (нет страницы или файла, корзина), на
  черновик, через переадресацию (правило или прежний адрес).
- **Страницы:** нет описания — так же, как решает `<head>`: своё описание, у главной — описание сайта,
  иначе анонс. Одинаковые заголовки. Длинные заголовки (на заметку).
- **Потерянные страницы:** опубликована, скрыта из меню, на неё нет ссылок, а список родителя её не
  выводит. Список узнаётся по исходникам: шаблон или компонент в тексте, которые сами или через импорты
  зовут `listing(` или `children(…includeHidden`. Ссылкой считается и id в своих настройках сайта: так
  каркасы держат страницу корзины и политики.
- **Главная** не выбрана или не опубликована.
- **Медиа:** картинки без описания; картинка больше 1 МБ без уменьшенных копий или файл больше 10 МБ.
- **Настройки:**
  - robots.txt закрывает весь сайт;
  - не задан адрес сайта или своя страница 404;
  - формы без каналов уведомлений;
  - недоставленные уведомления;
  - ИИ-поиск выключен (на заметку).

**Кэш отчёта.** Отчёт считается при первом запросе и держится до любого доменного события. Очередь
уведомлений меняется без событий, поэтому отчёт живёт не дольше пяти минут. «Проверить снова» считает
мимо кэша.

**Скорость.** Тысяча страниц со ссылками считается за единицы миллисекунд; это проверяет тест с
порогом 200 мс.

**Менеджер.** На начальном экране переключатель «Таблица | Дерево | Диагностика» («Карта» стала
«Деревом»). У «Диагностики» — число ошибок и предупреждений. Вкладку видит только администратор.

**Проверки сервера** (`src/server-checks.ts`) корень регистрирует через `register`:
- автокопии выключены или последняя не сделалась (только у сайта в файле);
- сертификат HTTPS не выпускается, или сайт открыт по `http://` без своего HTTPS (кроме localhost);
- доступна новая версия — на заметку, в счётчик проблем не входит.

## Последствия

- Переезд со старого сайта — таблица CSV, без плагина. Хук `notFound` остаётся для правил, которые нельзя
  записать таблицей.
- Счётчик переходов пишет в базу на каждую переадресацию; это одна строка `UPDATE`.
- Проверки потерянных страниц и списков — эвристика по исходникам. Список, который строится иначе
  (например, собственным SQL в плагине), диагностика не увидит и может назвать страницу потерянной.
