# 0027. «Забыли пароль?»: ссылка из письма через почту уведомлений

- Статус: принято
- Дата: 2026-10-31

## Контекст

Забытый пароль сейчас можно сменить только с сервера: `cms users password <почта>`. Редактору это
недоступно, администратору нужен SSH. В Evo для этого есть плагин Forgot Manager Login: письмо со
ссылкой, по которой можно войти и сменить пароль.

Своей почты у менеджера нет. Почту настраивают в «Настройки → Уведомления» (ADR 0020): SMTP-сервер,
отправитель, получатели заявок и сбоев. Без неё сброс по ссылке невозможен.

## Решение

**Ссылка видна, только когда есть чем отправить письмо.** `GET /session` отдаёт `passwordReset: true`,
если канал почты в уведомлениях настроен. Тогда под паролем на входе появляется «Забыли пароль?». Без
почты ссылки нет, а маршруты сброса отвечают `manager.reset_unavailable` (409).

**Запрос письма** — `POST /password/forgot` с почтой.
- Ответ всегда `202` и пустой, есть такой пользователь или нет. Письмо уходит в фоне, поэтому и время
  ответа ничего не выдаёт.
- Запросы считаются до поиска пользователя, так что лимит не зависит от того, есть ли адрес. За
  15 минут допускается:
  - 3 запроса на почту с одного адреса;
  - 10 запросов на почту вообще;
  - 20 запросов с одного адреса на любые почты.

  Иначе чужой ящик можно было бы завалить письмами. Сверх лимита — `identity.too_many_requests` (429).

**Ссылка** — 256 бит случайности в адресе `/manager/reset?token=…`.
- В базе (`identity_password_resets`) лежит только хэш, как у сеансов. Ссылка действует 30 минут.
- Новый запрос отменяет прежние ссылки пользователя. Удачный сброс гасит все.
- Адрес берётся из настройки «Адрес сайта», иначе из запроса; за прокси с `--trust-proxy` это адрес из
  `X-Forwarded-*`.
- Таблица — этого сервера, а не сайта: в копию она не попадает, как и сеансы.

**Письмо** — простой текст и HTML с названием сайта и ссылкой, только на адрес самого пользователя.
- Отправляется напрямую (`notify.email.send`), мимо очереди уведомлений. Иначе действующая ссылка
  осталась бы в очереди, а очередь видна в менеджере.
- Повторов нет. Сбой отправки попадает в журнал сбоев, но без ссылки.

**Сброс** — `POST /password/reset`.
- Пароль проверяется по тем же правилам, до того как ссылка погаснет: слишком короткий пароль её не
  тратит.
- Ссылка гасится до хеширования, поэтому второй такой же запрос её уже не найдёт.
- Затем закрываются все сеансы пользователя, и страница ведёт на вход с сообщением «Пароль изменён».
- Устаревшая ссылка (`identity.reset_invalid`, 410) — спокойный экран и кнопка «Запросить новое
  письмо». `POST /password/check` проверяет ссылку сразу при открытии страницы, чтобы не придумывать
  пароль впустую.

**Аудит.** Сброс публикует своё событие `identity.password_reset`. Владелец сайта видит его в журнале
сбоев и получает в уведомлениях, как создание пользователя и смену роли.

## Последствия

- Восстановить доступ можно без SSH, если почта настроена; без неё всё по-прежнему — через
  `cms users password`.
- Доступ к ящику пользователя теперь равен доступу к его учётной записи в менеджере. Это обычная цена
  сброса по почте, а запись в журнале сбоев делает такой вход заметным.
- Ограничитель запросов живёт в памяти процесса, как и счётчик неудачных входов: после перезапуска счёт
  начинается заново.
