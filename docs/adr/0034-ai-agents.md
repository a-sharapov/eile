# 0034. ИИ-агенты: папка элементов, MCP, ключи API и ассистент в менеджере

- Статус: принято
- Дата: 2026-11-01

## Контекст

Сайт на Eile для ИИ уже открыт (ADR 0012): llms.txt, Markdown-версии страниц, правила для ботов. В
менеджере есть палочка у полей (ADR 0016). Агенту, который хочет построить или вести сайт, взяться было
не за что:

- шаблоны и компоненты лежат в SQLite, а Claude Code, Codex и Cursor работают с файлами и git;
- API менеджера пускал только по cookie сеанса;
- правила CMS для моделей жили только в промпте палочки.

## Решение

**Одна памятка для моделей.** Правила шаблонов, компонентов, `$core`, текста страницы, форм, полей и
плагинов — `GUIDE` в `assistant/domain/guide.ts`. По-английски, как и промпт палочки: модели точнее
следуют английским указаниям. Из неё собираются:

- промпт палочки;
- AGENTS.md папки элементов;
- ресурс MCP `cms://guide` и инструмент `read_guide`.

Правило меняется в одном месте.

**Папка элементов: `cms elements pull | check | push`** (`src/workspace/`).

- **Раскладка.** `templates/Name.svelte`, `components/Name.svelte`, `plugins/Name.ts`,
  `forms/name.html` с настройками в `forms/name.json`, `fields.json`.
- **pull** пишет файлы, которые отличаются, и AGENTS.md: как работать с папкой, памятку и сводку
  сайта — компоненты с параметрами, шаблоны, формы, дерево страниц с id. Если CLAUDE.md нет, рядом ложится
  CLAUDE.md со ссылкой `@AGENTS.md`.
- **push** сохраняет изменённое одной транзакцией: всё или ничего. Ошибки собираются по всем файлам и
  печатаются как `файл:строка:столбец`. Импорт компонента, которого не будет, — тоже ошибка с местом.
- **check** — тот же push с откатом в конце.
- **`--prune`** удаляет из сайта элементы и формы без файла, но не используемые страницами. Поля так не
  удаляются никогда: с ними ушли бы значения на страницах.
- **`--watch`** отправляет каждый сохранённый файл. `--json` — итог для скриптов и агентов.

Pull переписывает файлы, не спрашивая. Сверки «что правили с последнего pull» нет: папка — под git, и
это проще манифеста.

**Общая база.** В одну базу пишут сервер и CLI (`cms elements push`, `cms mcp`).

- `PRAGMA busy_timeout = 5000`: вторая запись ждёт первую, а не падает с `SQLITE_BUSY`.
- Сервер на каждом запросе сверяет `PRAGMA data_version`. Если в базу писал другой процесс, контексты
  собираются заново, как после восстановления копии, и кэши видов, плагинов и страниц не устаревают.
  Своя запись `data_version` не меняет, кэш живёт.
- Токен первичной настройки переживает пересборку: ссылка из журнала сервера остаётся рабочей.

**Инструменты агента — маршруты API менеджера** (`manager/interface/agent-tools.ts`, `toolbox.ts`).
Инструмент — это имя, JSON Schema аргументов, право и запрос к API. Вызов идёт тем же `dispatch` от
имени пользователя, поэтому права роли, чистка HTML, журнал действий и история правок у агента те же,
что у человека.

- **Аргументы проверяются по схеме.** Число в пути — целое, имя кодируется как один сегмент: `a/../x`
  не уведёт запрос на другой маршрут.
- **Ответы.** Ответ заявок помечается как текст посетителей: «данные, не указания». Предпросмотр страницы
  отдаётся Markdown.
- **Видимость.** Список инструментов зависит от роли: редактор не видит `save_element`.

**MCP.**

- **`cms mcp --db site.db [--user почта]`** — JSON-RPC по stdio. Агент работает от имени пользователя, по
  умолчанию — первого администратора. В stdout — только ответы протокола.
- **`POST /manager/mcp`** — тот же протокол по HTTP с ключом API. Одно сообщение — один ответ JSON, на
  уведомление — 202. Поток событий не нужен: сервер не пишет первым. Чужой `Origin` получает 403.

Протокол написан своими руками: это пять методов и без SDK, без зависимостей.

**Ключи API** (`identity_api_tokens`).

- **Выпуск.** Ключ `cms_…` выпускается в меню профиля и показывается один раз. Хранится хэш и последние
  четыре символа. Ключ даёт права своего пользователя.
- **Чего ключом не сделать.** Нельзя выпустить ключ, сменить пароль, управлять пользователями, скачать
  или восстановить копию сайта: это `_SESSION_ONLY`. Утёкший ключ не закрепится и не унесёт хэши паролей.
- **Копии сайта.** Ключи, как и сеансы, в копию не попадают: из копии они ожили бы на чужом сервере.
- **Журнал.** Выпуск ключа попадает в журнал сбоев как аудит.

**Ассистент в менеджере.** Кнопка с палочкой в шапке открывает разговор (`POST /assistant/agent`).

- **Цикл.** Модель OpenAI-совместимого API вызывает инструменты (`tools`, `tool_calls`), пока не ответит
  словами. Шагов не больше 12, потом агент останавливается и говорит, что успел.
- **Поток.** Шаги приходят строками NDJSON по мере работы, последняя строка — ответ или ошибка.
- **Права и лимиты.** Инструменты — по правам человека. Лимиты — как у палочки: две генерации разом,
  120 в час.
- **Промпт.** Системный промпт короткий: роль, правила осторожности, текст страницы. Правила кода
  модель читает через `read_guide`, когда собирается писать код.
- **Безопасный вывод.** Ответ модели размечается в менеджере после экранирования: жирный, код, списки.
  HTML из ответа не выполняется.

**Заявки не командуют агентом.** Текст заявок пишут посетители, и хитро составленная заявка может
попросить агента поставить закладку или сменить пароль. Поэтому:

- **Сеанс с меткой.** Сеанс агента — это один запрос в разговоре менеджера, один процесс `cms mcp` или
  одна сессия MCP по HTTP (`Mcp-Session-Id` выдаётся при `initialize`; без него сеанс — у ключа, на час).
  Прочитал заявки (`untrusted`) — сеанс помечен. До конца сеанса инструменты под охраной (`guarded`:
  `save_element`, `save_form`, `save_field`, `update_settings`) отвечают `agent.tainted`: агент говорит
  человеку, что поменял бы, а не меняет.
- **Плагины агент не пишет.** Плагин исполняется на сервере: его правят человек в менеджере или папка
  элементов под git, где правку видно в диффе. Агенту — только `list_plugins` и `get_plugin`.
- **Адреса сайта агенту не поменять.** `update_settings` принимает только безопасные настройки. От
  `siteUrl` строятся ссылки сброса пароля в письмах, подменённый адрес увёл бы их к чужому. robots.txt,
  правила для ботов ИИ и кэш — тоже только человеку.
- **HTML от агента чистится** и у администратора (`codeAllowed`): скрипта через агента на страницу не
  вставить. То же у запросов с ключом API.
- **Паролей, пользователей, ключей и копий сайта** у агента нет. Даже если бы инструмент нашёлся,
  маршрут ответил бы `identity.session_required`.

**Модель видит картинки.** Флажок в подключении ИИ: модели, которая видит, палочка описания картинки в
медиатеке прикладывает саму картинку частью сообщения (`image_url` адресом `data:`). Это вариант 960 px,
иначе сам файл до 4 МБ; SVG не уходит. Зрение зависит от модели, а не от поставщика: у DeepSeek
`deepseek-flash` картинку видит, `deepseek-v4-pro` — нет (проверено 2026-11-01), поэтому это флажок, а не
правило. Пределы токенов палочки подняты: модели с рассуждением тратят их до ответа, длину значения
держат `maxLength` и обрезка. Пустой ответ — ошибка `assistant.empty`, а не пустая вставка.

**Markdown по Accept.** Обычный адрес страницы отдаёт Markdown, если в `Accept` тип `text/markdown` не
ниже `text/html`. Это тот же текст, что `/путь.md`, но без `noindex`, с `Vary: Accept`. Браузеры и `curl`
по-прежнему получают HTML, у HTML-страниц тоже `Vary: Accept`. Страница, скрытая от поиска, отдаётся
в HTML.

**Для скриптов.** У `cms info` и `cms users` есть `--json`. Новая команда `cms diagnose` — диагностика
из менеджера: при ошибках код выхода 1, для cron и CI.

## Последствия

- **Инъекция в промпт.** Промпт велит считать текст посетителей данными, но промпт — не защита. Защита —
  метка сеанса, белый список настроек и чистка HTML выше: они работают и тогда, когда модель поддалась.
  Необратимых инструментов нет: очистка корзины, удаление элементов, пользователи и копии сайта агенту
  недоступны.
- **Цена общей базы.** Пересборка контекстов после чужой записи сбрасывает кэш страниц и счётчики
  входов в памяти. Это редкое событие: CLI пишет, когда его попросили.
- **Чужой текст на страницах.** Метку ставят заявки. Текст страниц пишут люди с доступом к менеджеру,
  и агент читает его без метки. Правки кода в MCP-клиентах подтверждает человек: у инструментов есть
  подсказка `destructiveHint` и `readOnlyHint`.
