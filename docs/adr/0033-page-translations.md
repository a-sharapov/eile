# 0033. Набор переводов: перевод указывает на исходную страницу

- Статус: принято
- Дата: 2026-10-31

## Контекст

Многоязычный сайт на Eile собирается из веток по языкам (ADR 0013): `/kontakty` и `/en/contacts` — разные
страницы, и связи между ними не было. Поисковикам нужны ссылки `hreflang`, иначе они считают переводы
отдельными страницами или показывают не тот язык. Шаблону нужен переключатель языка, который ведёт на ту же
страницу на другом языке, а не на главную. В Evo это делал Babel: каждый документ хранил список «язык → id»
своих переводов, и правка одной страницы переписывала все.

## Решение

**Перевод указывает на исходную.** У страницы есть поле `translationOf` — id исходной страницы. Набор
переводов — исходная и все страницы, которые на неё указывают. Связь задаётся одной правкой одной
страницы, другие не переписываются.
- Перевод перевода встаёт в тот же набор: сценарий сворачивает цепочку к исходной.
- Страница со своими переводами переводом не становится (`content.translation_has_translations`): иначе
  набор распался бы на цепочку. Сначала её переводы связываются с другой исходной.
- Сама на себя — отказ (`content.invalid_translation`), несуществующая — `content.translation_not_found`.
- Язык не проверяется при связывании: он наследуется по ветке и меняется вместе с ней. Два перевода на
  один язык допустимы, наружу идёт первый: исходная, затем по id.
- Удалили исходную из корзины — переводы остаются страницами без набора.

**Наружу.**
- В шапке страницы — `<link rel="alternate" hreflang>` на каждый язык набора и `x-default` на исходную.
  В набор входят опубликованные HTML-страницы, открытые поиску, кроме страницы 404; у порций 2, 3…
  списка переводов нет. Если `hreflang` уже стоит в шаблоне, свой не добавляется.
- В `sitemap.xml` — то же через `xhtml:link`.
- `$core` даёт `translations(id?)`: `{ language, url, title, current }` для переключателя языка, исходная
  первой. Без переводов — пустой список, чтобы переключатель не рисовался.

**Кэш.** Шапка и переключатель зависят от других страниц, поэтому кэш страницы помечается тегом набора
`translations:<исходная>` и ветками переводов. События страниц несут `translationOf` и при смене связи
`previousTranslationOf`: правка любого перевода сбрасывает всех в наборе, и старом, и новом.

**Менеджер.** На вкладке «Настройки» многоязычного сайта есть раздел «Переводы»: выбор исходной и
весь набор со статусами и ссылками.

## Последствия

- Колонка `content_pages.translation_of` и индекс по ней; копия сайта переносит её как любую колонку.
- Для сайта на одном языке ничего не меняется: раздела в менеджере нет, `hreflang` не выводится.
- `og:locale` не ставится: из кода языка (`en`) не вывести страну, которую он требует.
