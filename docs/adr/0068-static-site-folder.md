# 0068. Папка-сайт: статический сайт из связанной папки

- Статус: принято
- Дата: 2026-11-08

## Контекст

Рядом с Evo на gabriel.by лежала папка `/razbor/` — статический сайт: сборка Astro (`base: '/razbor'`,
`trailingSlash: 'always'`), HTML, CSS, JS, шрифты, картинки, ролик и HDR-карта для сцены Three.js, 14 МБ.
Apache отдавал её как есть, раньше `index.php`. Сайт шлёт заявки в API плагина ([ADR 0067](0067-plugin-requests-and-schedules.md)).

Связанная папка ([ADR 0065](0065-linked-folders.md)) этого не умеет и не должна: она кладёт файлы в медиатеку
строками, а HTML, CSS и JS медиатека не принимает — с адреса сайта они открыли бы дорогу XSS от любого, кто
загружает файлы. Папка сборки — другое: её кладёт администратор сервера, как шаблоны.

## Решение

**Папка-сайт — связанная папка с флагом `--static`.**

```
cms media link <папка> --into <приставка> --static [--dry-run] [--json]
cms media unlink <приставка>
```

- **Файлы — не медиатека.** Строк в `media_files` нет, сверки нет: в базе — только строка папки в
  `media_links` с `static_site = 1` (миграция `media/008_static_sites`). Новый и изменённый файл виден сразу,
  повторять команду после новой сборки не нужно. `media()`, `image()`, менеджер медиатеки и «где используется»
  таких файлов не видят.
- **Вид папки выбирается при первой связке.** Повтор без флага — та же папка-сайт (без папки — сверка всех
  папок, у папки-сайта она лишь проверяет, что папка есть). Сменить вид связанной папки нельзя
  (`media.link_kind`): из медиатеки ушли бы описания, а HTML открылся бы там, где его не ждали; — сначала
  `cms media unlink`. `--serve-original` с `--static` — `media.static_original`: папка-сайт и так отдаётся по
  своим адресам. `media.json` у папки-сайта не читается.
- **Приставка** — по тем же правилам: латиница в нижнем регистре, не `manager`, `media`, `_cms`, не вложена в
  другую связанную папку (`media.prefix_overlap`).

**Отдача — `/<приставка>/…`, только GET и HEAD.**

- `/<приставка>` — 301 на `/<приставка>/` (query сохраняется); адрес каталога (`/razbor/`, `/razbor/about/`) —
  его `index.html`; каталог без `/` в конце — 301 на адрес со слэшем. Так ведёт себя сборка с
  `trailingSlash: 'always'` на любом статическом хостинге.
- **Нет файла** — `404.html` из корня папки со статусом 404; без неё — страница 404 сайта. Адреса под
  приставкой принадлежат папке: страницы, правила переадресации и плагины их не получают (иначе
  `/razbor/missing/` у сайта без адресов на `/` ушёл бы 301 на `/razbor/missing`).
- **Типы** — по расширению, только то, из чего состоит статический сайт: `html`, `htm`, `css`, `js`, `mjs`,
  `json`, `map`, `webmanifest`, `xml`, `txt`, `svg`, картинки (`png`, `jpg`, `gif`, `webp`, `avif`, `ico`),
  шрифты (`woff2`, `woff`, `ttf`, `otf`), `mp4`, `webm`, `mp3`, `ogg`, `wav`, `pdf`, `glb`, `gltf`, `hdr`, `wasm`.
  Остальное (`.php`, `.env`, исходники) не отдаётся — как будто файла нет; `cms media link` перечисляет такие
  файлы.
- **Кэш браузера.** ETag — размер и время изменения файла (хэш не считается: файл ищется на каждый запрос), 304
  на `If-None-Match`. Файлы сборки с хэшем в имени — `_astro/…` (Astro) и `_app/immutable/…` (SvelteKit) —
  `public, max-age=31536000, immutable`; остальное, HTML в том числе, — `no-cache`: браузер сверяется по ETag.
  `404.html` — без ETag.
- **Сжатие.** Текст (HTML, CSS, JS, JSON, SVG, XML) до 1 МиБ — br или gzip по `Accept-Encoding`; сжатое
  запоминается по ETag и пути (`defineCompressionCache`, 16 МБ на процесс) — тот же кэш, что у страниц. Сжимаются
  байты файла, кодировка его текста не угадывается. Картинки, шрифты, видео — как есть, через sendfile, с Range
  (206/416): Safari без 206 не играет ролик.
- **Заголовки.** `nosniff` у всех; у HTML — те же, что у страниц сайта: `Referrer-Policy`,
  `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`; у шрифтов — `Access-Control-Allow-Origin: *`, как в
  медиатеке.

**Порядок.** Тот же шаг, что у файлов связанной папки по исходному адресу — после служебных адресов, раньше
страниц, правил переадресации и плагинов ([ADR 0065](0065-linked-folders.md), порядок целиком — в
[ADR 0067](0067-plugin-requests-and-schedules.md)). Приставки не вкладываются, поэтому два обработчика одного
шага друг другу не мешают.

**Безопасность.**

- Файл ищется заново на каждый запрос с той же защитой, что у связанной папки: адрес расшифровывается, часть
  `..`, `.`, пустая, с `\` или нулевым байтом — 404 сразу; настоящий путь (`realpath`) должен лежать внутри
  настоящего пути папки — символьная ссылка наружу не отдаётся; скрытое (`.env`, `.git/`) и `__MACOSX` — как
  будто файла нет.
- **HTML папки-сайта — код администратора на адресе сайта**, как шаблоны и скрипты сайта. Cookie входа в
  менеджер его скрипт не прочитает (`HttpOnly`), но запрос с той же страницы к `/manager/api` уйдёт с ней: менеджер,
  открывший такую страницу, действует от своего имени. Поэтому папку связывает только тот, у кого есть доступ к
  серверу и базе (`cms media link`), а не менеджер, и в неё не кладут чужие файлы: загрузки посетителей, FTP
  подрядчика.

**CLI и копии.** `cms media link` пишет «Папка … — сайт по адресу /razbor/», число и размер отдаваемых файлов
и пропущенные по типу. `cms info` — строка папки с пометкой «сайт», `cms backup` и экран копий в менеджере
перечисляют её среди связанных папок: в копию базы она не входит. Диагностика: папки нет на диске —
`media.linked_missing`; ссылка в тексте страницы на файл или каталог папки-сайта — не битая.

## Проверка

Бинарник `dist/cms` этой ветки вне репозитория, сайт из `cms new blog`, сборка `gabriel-razbor/dist` (Astro 4.15)
под `--into razbor --static`: «файлов 63 · 13,6 МБ», ничего не пропущено. `/razbor/` — 200, `text/html`, `no-cache`,
ETag, 24 485 байт; `/razbor/guided-tour` — 301 на `/razbor/guided-tour/`, там 200; `/razbor/_astro/index.Btfplvvf.css`
с `Accept-Encoding: gzip` — `immutable` и gzip; `/razbor/covers/working.mp4` с Range — 206,
`bytes 0-999/7728512`; `/razbor/hdr/*.hdr` — `image/vnd.radiance`; повтор с `If-None-Match` — 304. Страницы блога
рядом — как были (`x-cache: hit`).

## Что не сделано и почему

- **Предсжатые `.br` и `.gz` рядом с файлами.** Astro по умолчанию их не делает, а сжатие в памяти по ETag
  стоит раз на файл.
- **Папка-сайт из менеджера.** Связать папку на диске сервера может только тот, у кого есть доступ к серверу;
  HTML с адреса сайта — не то, что выдают правом на медиатеку.
- **`Last-Modified`.** Как и у `/media`: ETag хватает.

## Последствия

- Статический сайт рядом с сайтом Eile — одна команда, без nginx перед ним.
- API: `MediaLink.staticSite`, `LinkInput.staticSite`, `LinkReport.staticSite`, `UnlinkReport.staticSite`,
  `media.statics.resolve`, `LinkedDisk.entry`, `defineStaticHandler`, параметр `notFound` у `defineMedia`,
  `delivery.notFound`; `escapesFolder` — общий с исходными адресами.
