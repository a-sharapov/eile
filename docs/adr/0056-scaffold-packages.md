# 0056. Пакеты каркасов: zip с манифестом, `cms new <пакет>`, официальные пакеты в выпуске

- Статус: принято
- Дата: 2026-11-04

## Контекст

Каркасы `cms new` (ADR 0022) вшиты в бинарник: TypeScript с деревом страниц и текстами плюс исходники
`.svelte`. Для блога и магазина это удобно, но не для всего. Сайт кухонной студии с демо-фотографиями в
бинарник не годится. Фотографии тяжёлые, а у продукта правило: Eile не называет других проектов своего
владельца. Такой сайт нужен отдельным пакетом, нейтральным к поставщику: его ставят, когда он нужен, а
выпускают рядом с бинарниками.

Нужен общий механизм. Каркас должен ставиться из файла, папки или по адресу, а официальные пакеты должны
выходить с каждым выпуском. Пакет скачивается из сети, поэтому ни при установке, ни при проверке он не
должен исполнять код на сервере.

## Решение

### Формат

Пакет — архив zip. В нём `manifest.json` и файлы в раскладке папки `cms elements` (ADR 0034), к которым
добавлены тексты страниц и медиатека:

```
manifest.json            формат, имя, заголовок, язык, дерево страниц, свои настройки, описания картинок
templates/<Имя>.svelte   шаблоны
components/<Имя>.svelte  компоненты
scripts/<имя>.js         скрипты сайта для браузера (ADR 0039)
plugins/<Имя>.ts         плагины: ставятся только с --allow-plugins
forms/<имя>.html|json    форма и её настройки, как в папке элементов
fields.json              поля страниц
pages/<…>.html           тексты страниц, на которые ссылается манифест
media/<путь>             файлы медиатеки; путь в медиатеке — без media/
README.md, LICENSE…      документы пакета в корне: едут в архиве, на сайт не ставятся
```

```json
{
  "format": 1,
  "name": "beispiel",
  "title": { "de": "Beispiel", "en": "Example", "ru": "Пример" },
  "summary": {
    "de": "zwei Seiten, eine Komponente und ein Bild",
    "en": "two pages, one component and one image"
  },
  "language": "de",
  "siteName": "Beispiel",
  "kit": ["Menu"],
  "settings": {
    "kontaktSeite": {
      "value": "@{kontakt}",
      "note": "Seite, auf die der Link im Fuß führt"
    },
    "telefon": "+49 30 000000"
  },
  "media": {
    "bilder/sonne.png": { "alt": "Eine Sonne über einem grünen Hügel" }
  },
  "pages": [
    {
      "key": "start",
      "title": "Start",
      "template": "Seite",
      "contentFile": "pages/start.html"
    },
    {
      "key": "kontakt",
      "title": "Kontakt",
      "alias": "kontakt",
      "template": "Seite",
      "contentFile": "pages/kontakt.html",
      "children": []
    }
  ],
  "home": "start",
  "notFound": "kontakt"
}
```

- `format` — версия формата, сейчас 1. Если пакет новее, cms просит обновиться, а не гадает. Схема строгая:
  незнакомое поле — ошибка, ничего не теряется молча. Новое поле означает новую версию формата.
- `title` и `summary` — строка или тексты по языкам. Показывается язык CLI, иначе язык пакета (`language`),
  иначе первый.
- Страница манифеста — те же поля, что у `NewPage`: `title`, `template`, `alias`, `kind`, `longTitle`,
  `menuTitle`, `description`, `introText`, `contentType`, `linkTo`, `hiddenFromMenu`, `cacheable`,
  `searchable`, `socialImage`, `language`, `fields`, `children`. Текст страницы — `content` строкой или
  `contentFile` файлом из `pages/`. Даты публикации и `translationOf` в формат не входят: страницы пакета
  публикуются сразу, а id в пакете не бывает.
- Текст страницы — как его хранит Eile: HTML с `[[Компонент …]]`, `[#Form:имя]` и ссылками `[~…~]`.

**Ссылки — `@{ключ}`, как у встроенных каркасов, а не `[~ключ~]`.** `@{kontakt}` при установке становится
id, и одна и та же запись годится везде: в ссылке `[~@{kontakt}~]`, в параметре `[[PostList parent=@{blog}]]`,
в исходнике формы и в значении своей настройки. `[~ключ~]` покрыл бы только ссылки, и формат разошёлся бы со
встроенными каркасами. Голый id (`[~12~]`) в пакете — ошибка: на новом сайте он указал бы на чужую страницу.

**Пакет и `Scaffold` переводятся друг в друга.** У пакета нет своего установщика. `packageScaffold` собирает
из пакета `Scaffold`, и его ставит тот же `applyScaffold`, что и встроенные каркасы. Обратный путь —
`scaffoldPackage` и `cms scaffold export <каркас>`. Чтобы переводы шли без потерь, тип `Scaffold` расширен:

| Пакет                                                                    | `Scaffold`                                      |
| ------------------------------------------------------------------------ | ----------------------------------------------- |
| `name`, `siteName`, `language`, `description`, `kit`, `home`, `notFound` | те же поля                                      |
| `title`, `summary` по языкам                                             | строка на языке CLI                             |
| `templates/`, `components/`                                              | `templates`, `components`                       |
| `scripts/`                                                               | `scripts` (новое): сохраняются раньше элементов |
| `plugins/`                                                               | `plugins` (новое): сохраняются последними       |
| `forms/<имя>.html` + `.json`                                             | `forms[имя]` = настройки + `source`             |
| `fields.json`                                                            | `fields`                                        |
| `settings` строкой или `{ value, note }`                                 | `settings`: `string \| ScaffoldSetting`         |
| `media/<путь>` + `media[путь].alt`                                       | `media` (новое): `{ path, data, alt }`          |
| `pages` с `contentFile`                                                  | `pages` с `content`                             |

Пояснение к своей настройке (`note`) формат принимает уже сейчас. Ядро этой версии пояснений не хранит, и в
сайт уходит значение. `ScaffoldSetting` повторяет тип из ветки, где пояснения появляются в ядре: после
слияния `applyScaffold` передаст и их.

### Откуда ставится

`cms new <аргумент>`: встроенный каркас по имени ищется первым, затем:

| Аргумент                                              | Что это                              | Чем подтверждено, что пакет тот самый                   |
| ----------------------------------------------------- | ------------------------------------ | ------------------------------------------------------- |
| путь: с `/` или `\`, на `.zip`; папка рядом — `./имя` | архив или распакованная папка автора | ничем: файл уже на этой машине; `--sha256` — по желанию |
| `https://…`                                           | архив по адресу                      | **обязательный `--sha256`**                             |
| имя (`beispiel`)                                      | официальный пакет                    | SHA256SUMS выпуска этой версии cms                      |

**Адрес — только с `--sha256`, без режима «с предупреждением».** Без суммы cms отказывает до первого запроса.

- Шаблоны и компоненты пакета сервер исполняет при показе страниц, с глобальными объектами процесса, как
  элементы, которые администратор пишет сам: импорты ограничены (ADR 0003), а `Bun` и `process` видны. Пакет
  по адресу — это код из сети.
- https подтверждает хост, но не содержимое. По тому же адресу завтра может лежать другой файл, а хост могут
  взломать. Сумма от автора означает «ставлю ровно то, что мне дали», и команду можно повторить.
- Предупреждения приучают их пропускать. Кто готов доверять адресу без суммы, скачает файл сам и даст путь:
  решение тогда принято явно, а файл можно прочесть.
- Скачивание идёт только по https, http — только с этой машины. После переадресаций проверяется то же:
  переход на http — отказ. Правила те же, что у `safeDownload` (ADR 0048).

**Официальный пакет — из выпуска этой версии, а не последней.** Лента та же, что у `cms update`: GitHub или
`CMS_RELEASES_URL`, с `CMS_RELEASES_INSECURE` (ADR 0048). Из выпуска `v<версия этой cms>` берутся
`<имя>.zip` и `SHA256SUMS`, и сумма сверяется до чтения архива. Пакет проверен вместе с той версией, с которой
вышел: шаблоны пакета пользуются `$core` этой версии. Доверие то же, что у `cms update`: та же лента, тот же
SHA256SUMS. Нет выпуска этой версии (сборка из исходников) или нет пакета — «Нет каркаса…» со списком
встроенных и причиной.

### Что исполняется

При установке не исполняется ничего из пакета:

- манифест — данные;
- шаблоны и компоненты только компилируются: проверка при сохранении не импортирует модуль;
- скрипты сайта — код для браузера, сервер их только разбирает.

**Плагины без `--allow-plugins` не ставятся.** Плагин — TypeScript, который сервер загружает и исполняет на
каждом запросе и на событиях. Сохранённый плагин загрузился бы ещё до конца установки, на её же событиях.
Поэтому:

- без флага пакет с `plugins/` не проходит проверку;
- с флагом cms печатает предупреждение, для пакета из сети — ещё одно: «не ставьте никогда»;
- плагины сохраняются последними, после страниц и настроек: их хуки не срабатывают на событиях установки;
- пробная установка плагинов не сохраняет никогда;
- официальным пакетам плагины не разрешены: `scripts/release.ts` собирает их без плагинов.

Совет для пакета из сети с плагинами — не ставить. Отказ без флага и предупреждение с флагом говорят это при
каждой установке.

### Проверка до записи

`checkPackage` — тот же путь для `cms new`, `cms new --check`, `cms scaffold pack` и сборки выпуска:

1. **Архив** (`readPackageZip`). Сначала по каталогу, до распаковки:
   - пути: без `\`, абсолютных путей, `C:`, управляющих символов, пустых частей, `.` и `..`;
   - символьные ссылки (тип Unix во внешних атрибутах) и шифрование — отказ;
   - имена, одинаковые без учёта регистра, — отказ: на macOS, Windows и в медиатеке это один файл;
   - файлы только известных видов; следы архиваторов (`__MACOSX/`, `.DS_Store`, `Thumbs.db`) пропускаются;
     одна папка верхнего уровня с манифестом («запаковать папку целиком») снимается;
   - размеры по заголовкам — пределы ниже.

   Только потом распаковка: zlib останавливается на заявленном размере, затем сверяются размер и CRC.
   Заголовок, который занижает размер (zip-бомба), память не раздует. Папка читается по тем же правилам,
   символьные ссылки в ней — тоже отказ. Скрытое (`.git`) и архив в корне не читаются.
2. **Манифест**: формат и схема целиком, ошибки — все сразу, с местом (`pages[1].template is required`).
3. **Ссылки**, без сайта:
   - ключи страниц: повторы, `home`, `notFound`;
   - `@{ключ}` в текстах, формах и настройках;
   - `[[Компонент]]` — среди своих и набора;
   - `[#Form:имя]` — среди форм пакета;
   - шаблоны страниц, `contentFile`, `/media/…` в тексте и картинки в полях `image` — среди файлов пакета;
   - незнакомые компоненты набора, неиспользованные `pages/*.html`;
   - пути медиатеки (нижний регистр) и её типы (`contentTypeOf`, ADR 0039);
   - имена плагинов и сами плагины без флага.
4. **Элементы — проверкой `cms elements check`**: `push(…, { dryRun: true })` на сайте в памяти, с набором.
   Компиляция, имена, импорты, формы и поля. Ошибки печатаются так же: `файл:строка:столбец сообщение код`.
5. **Пробная установка**: `applyScaffold` на том же сайте в памяти. Что ловит сам интерпретатор (поле не
   назначено шаблону, алиасы, значения полей, описания картинок), ловится здесь, а отчёт пробной установки и
   есть сводка «что будет создано».

Настоящая установка — одной транзакцией: приветствие убирается и каркас ставится, всё или ничего. Отказ
`untouched` (на сайте своя работа) — как у встроенных каркасов. Сводка — в стиле `cms new`: страницы,
элементы, поля и формы, медиатека; перед ней строка с источником и тем, чем сверена сумма. Варианты размеров
картинок ставит в очередь `media.files.save`, а нарезает сервер (ADR 0046). `cms new` разбирает очередь сразу,
поэтому `srcset` готов к первому запуску.

### Пределы

| Что               | Предел | Почему                                                          |
| ----------------- | ------ | --------------------------------------------------------------- |
| файл медиатеки    | 25 МиБ | `MAX_MEDIA_SIZE` самой медиатеки                                |
| любой другой файл | 2 МиБ  | предел скрипта сайта; шаблоны и тексты на порядки меньше        |
| всё распакованное | 64 МиБ | стартовый сайт с десятком фотографий; всё держится в памяти CLI |
| архив             | 65 МиБ | то же плюс заголовки zip; скачивание обрывается на пределе      |
| файлов            | 1000   | с запасом для каркаса; защищает от архива из миллиона пустяков  |

### Сборка архива: `cms scaffold pack`

Архив должен повторяться побайтно: одна папка даёт одну сумму на любой машине.

- Файлы идут по порядку путей в кодах символов (не `localeCompare`), время — 1 января 1980 (`ZIP_EPOCH`).
  Время DOS записывается в местном времени, а эта дата одна в любом часовом поясе.
- Сжатия нет (`store`). Байты deflate зависят от версии zlib, байты store — только от файлов. Тексты пакета
  весят десятки килобайт, фотографии уже сжаты, так что выигрыш от deflate мал, а повторимость дороже.
- Тексты читаются с LF и без BOM, как папка элементов (ADR 0049). Папка после git с `core.autocrlf` на
  Windows даёт тот же архив, что на Linux.

`pack` проверяет папку так же, как установка, и печатает SHA-256 — её дают вместе с адресом пакета.
`cms scaffold export <каркас>` выгружает встроенный каркас папкой пакета: старт для автора и для тестов.
Ключа страницы для имени файла нет — текст ложится в `pages/<номер>.html` по порядку обхода дерева.

### Официальные пакеты в выпуске

- Лежат в `packages/<имя>/` репозитория. Имя в манифесте совпадает с папкой. `cms-…` занято файлами выпуска,
  такие имена формат не принимает.
- `scripts/release.ts pack` после бинарников собирает каждый пакет в `dist/release/<имя>.zip` и дописывает
  строку в SHA256SUMS. `release.ts packages [--out <папка>]` собирает только пакеты — для пробы.
- `release.yml`: в задании `publish` перед упаковкой добавлен `bun install`, потому что проверке пакета нужен
  компилятор Svelte. `gh release create` берёт `dist/release/*.zip`, а это и сборки Windows, и пакеты.
- `packages/beispiel/` — образец: две страницы, шаблон, компонент `Bild` и картинка 720×400 (2 КБ), своя
  настройка с пояснением и ссылки `@{…}`. На нём тесты проходят весь путь: папка → архив → лента с SHA256SUMS
  → `cms new beispiel`.

## Последствия

- Каркас может жить вне бинарника и выходить с выпуском, а сторонний пакет ставится одной командой с
  проверкой. Механизм один: встроенный каркас и пакет ставит один `applyScaffold`, и всё, что умеет
  интерпретатор, умеют оба.
- Пакет из чужих рук — это код, который сервер исполняет при показе страниц. Сумма подтверждает, что файл
  тот самый, но не что автор честен. Справка и это решение говорят об этом прямо. Песочницы для шаблонов нет,
  и пакеты её не добавляют.
- Архивы без сжатия крупнее на размер текстов, то есть на десятки килобайт.
- Пакет ставится только на новый сайт или нетронутое приветствие. Обновления пакета на живом сайте нет: как и
  каркас, пакет — стартовая точка, а не тема.
- Задание `publish` теперь ставит зависимости, это примерно 20 секунд выпуска.

### Не проверено

- Настоящий выпуск на GitHub: путь «лента → `<имя>.zip` → SHA256SUMS» проверен на подставленной ленте,
  переадресация GitHub на `objects.githubusercontent.com` — нет.
- Сборка пакетов на раннерах Windows (`release.ts pack` в задании `windows`): пути там через `posixPath`, но
  запуска на Windows не было.
- Архивы из чужих архиваторов, кроме собранных `zip()` вручную в тестах: 7-Zip, Проводник, `ditto` на macOS.
