# 0001. Bun + SQLite + Svelte, поставка одним бинарником

- Статус: принято
- Дата: 2026-10-29

## Контекст

Нужна CMS в духе Evo: быстрая, простая в установке, с правкой шаблонов в браузере. Рассматривали два стека:

- **Elixir + Phoenix + LiveSvelte + Ash** — BEAM, LiveView в админке, Ash для ресурсов;
- **Bun + SQLite + Svelte** — один рантайм, один язык, сборка в один исполняемый файл.

## Решение

Bun 1.4, `bun:sqlite`, Svelte 5. Поставка — один файл, собранный `bun build --compile`.

## Почему

- **Простота установки — суть Evo.** «Скачал файл, запустил» — современный аналог «залил по FTP». Модель
  «один бинарник + SQLite» уже доказала себя на рынке (PocketBase).
- **Скорость определяет кэш, а не рантайм.** Готовый HTML из памяти отдаётся за доли миллисекунды
  (замер на каркасе: 0,2 мс), первый рендер страницы занимает 0,4 мс.
- **Сниппеты пишут в браузере.** Компиляция Svelte и загрузка модулей во время работы для Bun естественны
  ([ADR 0003](0003-svelte-views-compiled-at-runtime.md)). В Elixir расширения — это пересборка релиза или
  `Code.eval_string`.
- **Ash плохо подходит под TV:** ресурсы Ash описываются на этапе компиляции, а поля пользователь создаёт во
  время работы сайта.
- **LiveSvelte — это два-три рантайма** (BEAM, браузер, Node.js для SSR). Это ломает идею одного бинарника.
- **Аудитория.** Компоненты и плагины будут писать веб-разработчики, а они знают JS и Svelte.

## Последствия

- Синхронный SQLite позволяет делать синхронные порты ([ADR 0002](0002-ddd-modular-monolith.md)).
- Один писатель SQLite: для CMS этого достаточно. Режим WAL даёт параллельное чтение.
- Бинарник около 105 МБ, почти весь объём — рантайм Bun.
- Кластер и тысячи сайтов на одной платформе — не цель. Если понадобятся, пересмотрим это решение.
