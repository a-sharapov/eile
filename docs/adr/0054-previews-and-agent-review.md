# 0054. Ссылки предпросмотра и проверка правок агентов

- Статус: принято
- Дата: 2026-11-03

## Контекст

Две задачи об одном: показать то, чего ещё нет на сайте.

- **Агентство и клиент.** Агентство собирает страницу и хочет показать её клиенту до публикации. У клиента
  нет входа в менеджер, а предпросмотр `/pages/:id/preview` открывается только вошедшему.
- **Агент и владелец.** Агент через MCP правит сайт сразу (ADR 0034): опубликованная страница меняется в
  ту же секунду, откатить её можно только историей. Владелец хочет смотреть правки агента пачкой, как pull
  request: разница, предпросмотр, затем «принять» или «отклонить».

**Может ли у опубликованной страницы быть неопубликованная правка?** Нет. У страницы одно состояние,
публикация — флаг (`Page.published`), история (ADR 0026) хранит прошлые версии, а не будущие. Поэтому
ссылка предпросмотра показывает черновик (неопубликованную страницу) или страницу с правками набора
агента — второго источника «будущих» правок нет.

## Решение

Новый контекст `review` (`src/contexts/review/`): ссылки, наборы, предложения, их сравнение и
предпросмотр. Перехват правок агента и их применение — в `manager`: там маршруты, права и чистка HTML.

### Ссылки предпросмотра

- **Адрес** — `/_cms/preview/<токен>`. Токен — 12 знаков поиска (selector) и 32 знака секрета (verifier),
  base64url, 72 + 192 бита. В базе — selector и SHA-256 секрета: утечка базы ссылок не открывает.
- **Сравнение за постоянное время.** Строка ищется по selector, хэш секрета сравнивается
  `crypto.timingSafeEqual`. Неизвестный selector сравнивается с пустым хэшем — время ответа то же.
- **Лимит поисков** — в памяти процесса, по адресу посетителя: 120 в минуту; после 20 неверных за 10 минут
  адрес получает 429 и на верные ссылки. Подобрать 192 бита и так нельзя, лимит не даёт и пробовать.
- **Срок** — 7 дней по умолчанию (настройка «Предложений», 1–90), свой у каждой ссылки. Ссылок на
  страницу — сколько угодно, у каждой подпись «для кого». Список, отзыв и счётчик открытий — в менеджере.
  Истёкшая ссылка видна в списке ещё сутки, затем удаляется.
- **Цель** — неопубликованная страница или страница набора правок. На опубликованную ссылку не выдать
  (`review.page_published`): у неё есть свой адрес.
- **Только своя страница.** Токен открывает одну страницу; дерева, других страниц, менеджера и API за ним
  нет. Ссылку выдаёт вошедший человек: ключом API её не получить (`_SESSION_ONLY`) — агент не выведет
  черновики наружу.
- **Ссылки — данные этого сервера**, как ключи API: в копию сайта не попадают
  (`REVIEW_SERVER_TABLES`).

**Ответ — как настоящая страница, но не для всех.**

- Рендер — тот же `delivery.preview`: шаблон, компоненты, формы, файлы стилей (ADR 0047). Кэша страниц он
  не касается, маячка статистики и полосы правки нет.
- **Ничего не кэшируется:** `Cache-Control: private, no-store`.
- **Поисковики не индексируют:** `X-Robots-Tag: noindex, nofollow, noarchive` и `<meta name="robots">`.
- **Токен не уходит в Referer:** `Referrer-Policy: no-referrer` — шрифты и картинки с чужих сайтов его не
  увидят.
- **Во фрейм не встроить:** `frame-ancestors 'none'`.
- **Плашка.** «Vorschau — nicht veröffentlicht» на языке страницы (de, en, ru, иначе en) — снизу по центру,
  inline-стилями, мимо стилей сайта.
- **Формы не отправляются.** Поля — внутри `<fieldset disabled>`, у формы `method="dialog"` вне диалога (не
  шлёт ничего) и нет `action`; под формой — пометка.

### Проверка правок агентов

**Когда включена.**

- **Для всех агентов** — настройка в «Предложениях». Меняет её только администратор, вошедший в менеджер.
- **Для ключа** — отметка «Правки ждут проверки» у ключа API (`identity_api_tokens.review`). Ставит
  владелец ключа, тоже только войдя в менеджер.
- Отметка ключа только добавляет проверку: ключ без отметки общей настройки не обходит.

**Кто агент.**

- Запрос с ключом API — к API напрямую или через `/manager/mcp`.
- `cms mcp` на сервере — без ключа, проверяется по общей настройке.
- **Ассистент в менеджере — не агент для проверки.** Его запускает вошедший человек и видит каждый шаг, как
  если бы правил сам. Проверка — для правок, за которыми никто не следит.

**Что предлагается.** Маршруты API, которые при проверке не выполняются, а становятся предложением
(`review-api.ts`, таблица `gate`):

- страницы — создание, правка свойств и текста, поля, перенос, публикация и снятие, корзина и возврат,
  возврат к версии истории;
- элементы — шаблоны, компоненты, скрипты.

Правка проходит те же проверки, что и без проверки, но без записи:

- **HTML чистится** уже в предложении — проверяющий видит то, что ляжет на сайт;
- **страница** строится доменом content (`pages.simulate`): алиас, заголовок, ссылка, расписание, поля шаблона;
- **элемент компилируется** (`design.elements.check`): ошибка приходит агенту сразу со строкой и столбцом;
- **права роли** проверяет маршрут, как всегда.

**Что отклоняется.** Формы, поля, настройки, подписи файлов, редиректы, плагины, корзина и всё прочее, что
меняет сайт, — отказ `review.not_reviewable`: «скажите человеку, что поменяли бы». Почему отказ, а не
предложения:

- у форм вебхуки с секретом и маршруты уведомлений, у настроек — адрес сайта и правила для ботов;
- у этих правок нет ни сравнения текстом, ни предпросмотра, из которых принимают решение;
- новый маршрут, который меняет сайт, при проверке по умолчанию тоже отказ: забыть его в таблице безопасно.

Загрузка в медиатеку разрешена только по новому пути: новый файл сайт не меняет, а без картинок новой
странице не обойтись. Замена существующего файла — отказ.

**Набор правок.**

- **Один набор — один сеанс агента:** сессия MCP (`Mcp-Session-Id`), процесс `cms mcp` или ключ без сессии.
- **Правки одной цели в наборе сливаются** в одно предложение: последнее значение каждого свойства.
- **База** — каким каждое место было, когда агент тронул его впервые. По ней видны конфликты.
- **Новая страница.** Создание занимает id сразу (`content.pages.reserveId`: `sqlite_sequence` + 1), и
  агент продолжает с ним в том же наборе: правит, публикует, вкладывает страницы, ставит `[~id~]`. Принятая
  страница создаётся с этим id. Отклонённая оставляет пропуск: id и так не переиспользуются.

**Ответ агенту — квитанция.**

- Инструмент отвечает `202 { pending: true, changeSet, proposal, target, operations, message }`, у
  создания — и `id`.
- Инструменты агента: `list_proposals` (свои наборы и включена ли проверка), `submit_changes` (заголовок,
  описание, уведомление владельцу), `withdraw_proposal`.
- Режим объясняют `instructions` MCP, пока он включён, и тема `review` памятки (`read_guide`).

**Уведомление.** `submit_changes` публикует `review.change_set_ready`. Корень приложения отправляет письмо
или сообщение в Telegram — каналами событий сайта (`notify.settings.incidents`), со ссылкой на набор в
менеджере, если задан адрес сайта. Отдельного порога важности у него нет: владелец сам просил проверку.

**Разбор в менеджере** — раздел «Предложения» (`/manager/proposals`).

- **Список наборов**: агент и его ключ, сколько ждёт, принято, отклонено и сколько конфликтов.
- **Набор**: описание агента (как текст: это пояснение, а не указание) и разница по каждому предложению:
  - свойства и поля — «сейчас → предложено»;
  - текст страницы и исходник элемента — построчно, с изменёнными словами и с разметкой: проверяющему
    важно, не принёс ли агент лишний тег или компонент;
  - перенос — «был раздел → стал раздел».
- **Сравнение считает сервер** (`review/domain/text-diff.ts`): общие начало и конец снимаются без таблицы,
  поэтому правка в середине длинного исходника быстрая.
- **Решения:** принять всё, принять выбранные, отклонить выбранные или всё.

**Принятие — обычным путём.**

- Принятое предложение выполняют те же операции, что и маршруты API (`Operations` в `api.ts`), от имени
  пользователя агента, как агент (`agent: true`): HTML чистится, история страницы подписана им, журнал
  «Обзора» — тоже.
- Порядок: элементы (компоненты раньше шаблонов), новые страницы от родителя к детям, затем правки.
- **Всё в одной транзакции:** отказ одного откатывает все, ошибка остаётся у предложения.
- Принимает человек с правами на то, что предложено (элементы — `design.edit`) и только войдя в менеджер:
  ключом агента свои предложения не принять.

**Конфликт** — место правили после предложения, и не так, как предлагает агент; страницу удалили; у
элемента сменилась ревизия. Такое предложение без отметки «принять всё равно» не принимается
(`review.conflict`). Рядом с нынешним значением видно, что видел агент. Совпало с предложенным — не
конфликт.

**Предпросмотр набора** — та же отрисовка, что у ссылки:

- страница — какой станет (`pages.simulate` → `drafts.viewOf`);
- шаблоны и компоненты — из предложения: свой загрузчик видов с подменой исходников и своей памятью
  компиляций (`design.views.withSources`). Спецификаторы разрешаются синхронно, до первого `await`,
  поэтому два предпросмотра разом не путают подмены. CSS предложенного элемента не в файлах сайта и встаёт
  в страницу `<style>`.

Предпросмотр открывается в менеджере и по ссылке для клиента.

**Код агента в предпросмотре — в песочнице.** Ответ предпросмотра набора — `Content-Security-Policy:
sandbox allow-scripts allow-popups` без `allow-same-origin`:

- скрипт агента живёт в пустом origin, без cookie менеджера и без доступа к его API;
- он не примет свой набор руками вошедшего владельца;
- шрифты медиатеки отдаются с `Access-Control-Allow-Origin: *`, чтобы и в песочнице страница выглядела
  как на сайте.

Черновик человека — та же доверенность, что у сайта, и песочницы не получает.

**Текст посетителей по-прежнему закрывает код.** Метка сеанса (ADR 0034) проверяется до проверки правок:
прочитавший заявки агент не предложит даже шаблон.

## Последствия

- **Ограничения предпросмотра набора.** Меню и списки показывают сайт как сейчас: заголовки и новые
  страницы других предложений в них не видны. Скрипты и острова — живые версии: предложенный скрипт виден
  только в сравнении.
- **Чтение не видит предложений.** `get_page` и `view_page` при проверке показывают сайт как есть. Агенту
  об этом говорят квитанция, `instructions` и памятка, чтобы он не повторял правку.
- **Сравнение принятого.** У решённого предложения сравнение идёт с нынешним состоянием и обычно пустое.
  Прошлое страницы — в её истории.
- **Пропуски в id.** Отклонённые и отозванные новые страницы оставляют пропуски — так уже бывает после
  удаления навсегда.
- **Вне проверки.** Формы, поля и настройки при проверке агенту недоступны вовсе. Если агенту нужны и они,
  проверку включают для отдельного ключа, а не для всех.
