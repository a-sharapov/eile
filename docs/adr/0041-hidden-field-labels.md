# 0041. Подписи значений скрытого поля: `data-labels`

- Статус: принято
- Дата: 2026-11-03

## Контекст

Скрытое поле часто несёт ключ, а не текст для людей. Пакет заказа приходит параметром адреса
`?paket=planung` (`data-source="query:paket"`), письмо заказчику и тема уведомления печатают `{paket}` — и
заказчик читает «Paket: planung» вместо «KI-Küchenberater + KI-Planung». У списка и переключателей такой беды
нет: заявка хранит подпись варианта (`checkValues` берёт её из `options` поля). Внешнему сервису, наоборот,
нужен ключ: по нему CRM узнаёт тариф, а приёмники вебхука уже читают `values.paket`.

## Решение

**Разметка** — атрибут у самого поля, как остальные правила формы (ADR 0021):
`<input type="hidden" name="paket" data-source="query:paket" data-labels="berater=KI-Küchenberater|planung=KI-Küchenberater + KI-Planung">`.
- Записи `значение=подпись` через `|`. Значение — до первого `=`; в подписи `=` может быть, `|` — нет, как в
  `data-show-if`. Пробелы по краям не в счёт.
- Разбор (`parseLabels`) кладёт подписи в `options` поля — туда же, где варианты `<option>`. Дальше скрытое
  поле идёт путём списка: `fieldValue` показывает подпись, значение без подписи — как есть. Проверки «выберите
  вариант» у скрытого поля нет: значение по-прежнему решает источник.
- `data-show-if` сравнивает присланное значение, как раньше: `data-show-if="paket=planung"`.

**Снимок заявки.** `value` — подпись, как у списка, поэтому письмо (`{paket}`), тема и текст уведомления,
карточка и список заявок, CSV ничего о подписях не знают. Присланный ключ — в новом поле `raw`, оно есть
только у скрытого поля с подписями. Поиск находит заявку и по ключу, карточка показывает его серым рядом с
подписью. Поправили подписи — старые заявки не меняются: это снимок.

**Уведомление и список заявок.** Скрытых полей там нет; скрытое поле с подписями есть — его выбрали на
сайте, как вариант списка.

**Вебхук и плагины — без поломки приёмников.** `values` — значения, как их прислали: у скрытого поля с
подписями — ключ (`raw`), у остальных полей — как раньше. Подписи — отдельным объектом
`labels: { paket: "KI-Küchenberater + KI-Planung" }`, и только если в заявке есть скрытое поле с подписями:
тело вебхука других форм не меняется ни на байт. Событие `forms.submission_received` несёт те же `values` и
`labels` (без подписей — пустой объект).
- Не подпись вместо значения: приёмник, который сверяет `values.paket === 'planung'`, сломался бы, как только
  владелец сайта добавит подписи.
- Не `{ value, label }` в `values`: тип значения сменился бы у всех полей, а с ним — у каждого приёмника.

**Проверка при сохранении** — как у служебной cookie: форма не сохранится, если `data-labels` стоит не у
скрытого поля (`forms.labels_not_hidden`; у списка подписи — в вариантах), запись не `значение=подпись` или
значение повторяется (`forms.invalid_labels`). Менеджер показывает ошибку на своём языке (ru, en, de), агент
получает английский текст с именем поля и неверной записью. Форма, попавшая в базу мимо проверки (копия
сайта), не падает: неверные записи пропускаются.

**Редактор форм.** У скрытого поля — «Подписи значений» строками `значение | Подпись`, как варианты списка.
Сборка пишет `data-labels`, разбор читает его обратно: правка поля в редакторе подписи не теряет.

## Последствия

- В письмах и у менеджера — текст для людей, в вебхуке — ключ для машин и подпись рядом.
- Для формы без `data-labels` не меняется ничего: ни заявки, ни уведомления, ни тело вебхука.
- Подпись не может содержать `|`.
