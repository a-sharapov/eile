# 0063. Адреса в стиле Evo: суффикс, папки со слэшем, алиас вне адреса

- Статус: принято
- Дата: 2026-11-08

## Контекст

Адрес страницы в Eile — алиасы предков и её собственный, без окончания: `/katalog/pamyatnik`. Завершающий
`/` уходит 301 на адрес без него. Так и задуман канонический путь: один адрес на страницу.

Сайты на Evo устроены иначе, и переносить их нужно 1:1, иначе поисковики теряют страницы. На gabriel.by
(около 3100 документов, Evo 1.4.10) действуют четыре настройки и два флага документа:

- `friendly_url_suffix = .html` — окончание адреса документа: `/pamyatniki.html`. Алиас, в котором уже есть
  точка (`sitemap.xml`, `google-ads.xml`), суффикса не получает.
- `make_folders = 1` — документ с флагом `isfolder = 1` кончается на `/`: `/katalog/`. Это хранимый флаг, а
  не «есть дети»: 170 папок gabriel.by без детей, все 168 страниц городов — папки (`/baran/`).
- `alias_visible = 0` у документа — его алиас не входит в адреса потомков, сам он живёт по своему адресу.
  Разделы `cities` и `system` так прячут себя: город живёт на `/baran/`, а не на `/cities/baran/`.
- `use_alias_path = 1` — путь из алиасов; при `0` все адреса плоские: `/алиас.html`.

Evo находит документ по пути без суффикса (`documentListing`); два документа с одним путём делят адрес.

## Решение

**Стиль адресов — настройка сайта, по умолчанию прежний.** В `SiteSettings` два поля:

- `urlSuffix` — окончание документа: пусто (по умолчанию), `/` или расширение `.` + до 10 латинских букв и
  цифр (`.html`). Алиас с точкой его не получает.
- `folderSlash` — адрес папки кончается на `/` (по умолчанию нет).

Обе меняет только человек в менеджере (`_HUMAN_SETTINGS`, как адрес сайта и кэш): смена стиля меняет все
адреса сайта разом, ключ API или агент так делать не должны. Старые адреса при смене стиля не запоминаются:
стиль выбирают один раз, при переносе.

**Флаги страницы, как в Evo.** `folder` (`isfolder`) и `aliasInPath` (`alias_visible`, по умолчанию true) —
поля агрегата `Page`, колонки `folder`, `alias_in_path` (миграция `content/010_address_flags`; у страниц с
детьми `folder = 1`, чтобы сайт, включивший «папки со слэшем», получил `/` у разделов). Их видят
`PageView`, `PageNode`, API, инструменты агента, менеджер (раздел настроек страницы) и `NewPage` каркасов.

Когда у страницы появляется дочерняя (создание или перенос), она становится папкой — как в Evo. Сам флаг
не снимается: у папки может не быть детей. Прежний адрес (`/o-nas.html` → `/o-nas/`) записывается в
`content_old_paths` и ведёт 301 на новый. Перенос сайта флагов не трогает: они приходят из дампа как есть.

**Адрес.** Окончание — `/` у папки при `folderSlash`, иначе суффикс (если в алиасе нет точки), иначе пусто.
Ключ адреса — алиасы предков с `aliasInPath` и свой алиас, без окончания. Адрес = ключ + окончание; главная,
как и раньше, живёт на `/`. `PageView.path` и `PageNode.path` — уже адрес: им пользуются `link()`, `[~id~]`,
canonical, Open Graph, JSON-LD, sitemap.xml, llms.txt, поиск, крошки и меню набора, правила на `[~id~]`,
формы, статистика, предпросмотр, полоса правки, диагностика и «Открыть на сайте» в менеджере. Индекс дерева
(`_TREE`) собирается под стиль и пересобирается, когда стиль меняется.

**Единственность.** Два адреса на сайте не совпадают ни ключом, ни самим адресом (`content.address_taken`).
Со скрытым алиасом соседями по адресу становятся страницы разных веток, поэтому сохранение, которое меняет
адрес ветки (алиас, родитель, `aliasInPath`, возврат из корзины, флаг папки), проверяет всю ветку: начало
адреса родителя и адреса чужих страниц с теми же алиасами (и с суффиксом и без: `o-nas` и `o-nas.html` при
`.html` живут по одному адресу) считает рекурсивный SQL снизу вверх. Совпадение ключа при разных окончаниях
(`/a/` и `/a.html`) — тоже столкновение: иначе вариант `/a` не знал бы, куда вести.

**Отдача.** Путь запроса чистится от пустых сегментов, но завершающий `/` остаётся (`cleanPath`). Страница
ищется по точному адресу, затем по ключу (`content.published.locate`): без `/`, без суффикса.

- Канонический адрес — 200 и кэш под ним.
- Вариант (без суффикса, с лишним суффиксом, без `/` у папки, с `/` у документа) — 301 на адрес, query
  сохраняется.
- Прежние адреса страниц ищутся по всем вариантам пути; правила переадресации записаны без завершающего `/`
  и находятся по пути без него.
- Сайт без слэша в стиле (`folderSlash` выкл., суффикс не `/`), как и раньше, отправляет `/x/` без страницы
  301 на `/x`. Со слэшем в стиле `/` — часть адреса, такого шага нет.

**Порции списка.** Хвост `/<слово>-N` встаёт после ключа страницы, окончание страницы — после номера:

| Страница                   | Порция 2               |
| -------------------------- | ---------------------- |
| `/blog` (по умолчанию)     | `/blog/page-2`         |
| `/katalog/` (папка)        | `/katalog/page-2/`     |
| `/novosti.html` (документ) | `/novosti/page-2.html` |
| главная, папка             | `/page-2/`             |

Хвост узнаётся с любым окончанием (`/katalog/page-2`, `/novosti.html/page-2`), а не своё окончание — 301.
`listing().url(n)`, `pager()`, canonical, `prev`/`next` строят тот же адрес. Окончание берётся из адреса
страницы (`endingOf`: то, что идёт после алиаса), так что отдаче не нужен сам стиль.

**Markdown-версия** — ключ и `.md`: `/katalog/` → `/katalog.md`, `/o-nas.html` → `/o-nas.md`, главная —
`/index.md`; путь без `.md` ищется как вариант адреса.

**Перенос из Evo** (`cms import-evo`) читает `friendly_urls`, `friendly_url_suffix`, `make_folders`,
`use_alias_path`, `friendly_url_prefix` до страниц и ставит стиль адресов; `isfolder` и `alias_visible`
документа — флаги страницы (дамп без `isfolder` — папка та, у кого есть дети). `use_alias_path = 0`
переносится плоскими адресами: у каждой страницы `aliasInPath = false`, — и отчёт говорит об этом.
Выключенные `friendly_urls` и префикс адреса не переносятся — предупреждение. Пустой алиас Evo заменяет
id документа — так же делает перенос. Занятый адрес не роняет страницу: её алиас получает `-<id>`, отчёт
предупреждает. Заодно: weblink с целью `[~13~]` — ссылка на страницу 13, `searchable` документа переносится.

**Пакеты каркасов** флагов не получают: строгий формат манифеста (ADR 0056) отклоняет незнакомые поля
страницы, и `folder`/`aliasInPath` потребовали бы формата 3, а стиль адресов — ещё и настроек сайта в
манифесте. Встроенные каркасы на TypeScript флаги задать могут (`ScaffoldPage` — это `NewPage`).

## Последствия

- У существующих сайтов адреса не меняются: стиль по умолчанию — без окончаний, флаги ни на что не влияют,
  пока стиль не включён.
- На дампе gabriel.by все 2937 адресов живой карты сайта находят ту же страницу, что в Evo, и `link(id)` даёт
  тот же адрес.
- Смена стиля на работающем сайте меняет все адреса без переадресаций со старых — это осознанная операция
  человека, а не агента.
- Каждое сохранение страницы стоит ещё двух-трёх запросов (флаг до правки, начало адреса родителя, соперники
  по алиасу); перенос gabriel.by не замедлился — индекс `content_pages_alias` ускорил и проверку соседей.
- Путь `/cities/baran/` (через скрытый алиас) — 404, как и в Evo.
