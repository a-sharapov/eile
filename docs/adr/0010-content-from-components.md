# 0010. Контент страницы собирается из компонентов сайта

- Статус: принято
- Дата: 2026-10-29

## Контекст

В Evo текст страницы правят в TinyMCE, а сниппеты вставляют руками как `[[Ditto? &parents=`5`]]`:
редактору нужно помнить имена и параметры. У CMS уже есть теги `[[Name prop="x"]]` в контенте
(`<Content>` вызывает по ним компоненты), а компоненты — обычный Svelte с `$props()`. Сырой HTML в
`<textarea>` для редактора неудобен, а визуальный редактор, который молча выбрасывает непонятную ему
разметку, опасен для перенесённых из Evo страниц.

## Решение

Контент в менеджере — список **блоков**: текст и вызовы компонентов. Хранится он по-прежнему строкой:
HTML с тегами `[[…]]` между блочными элементами, так что сайт и импорт ничего не знают о блоках.

- **Блок компонента** — тег, стоящий отдельно: между блочными элементами или один в абзаце. Тег внутри
  текста (`Цена: [[Price id=3]] руб.`) остаётся текстом. Разбор менеджера совпадает с разбором сайта —
  это проверяет `tests/content-blocks.test.ts`.
- **Форма блока** строится по **сигнатуре компонента**: описание из `<!-- @component -->`, параметры из
  деструктуризации `$props()` — имя, комментарий над параметром как подпись, тип из TypeScript или из
  значения по умолчанию, варианты из объединения литералов (`'note' | 'warning'`), подписи вариантов — в том же
  комментарии: `/** Оттенок: note=Заметка, warning=Внимание */`. Сигнатуру считает
  контекст `design` по AST Svelte; менеджер получает каталог через `GET /manager/api/components`.
- **Текстовый блок** правится визуально (ProseMirror: абзацы, заголовки 2–4, жирный, курсив, ссылки,
  списки, цитаты, изображения из медиатеки). Если разметка не переживает разбор и сборку без потерь
  (классы, таблицы, комментарии, атрибуты, которых нет в схеме), блок открывается как HTML в CodeMirror —
  визуальный режим для него недоступен.
- Значения в теге пишутся так, чтобы сайт прочитал их тем же типом: строки в кавычках, числа и
  `true`/`false` без кавычек; пустое поле формы — значение по умолчанию, параметр в тег не пишется.

Поле типа `image` хранит путь файла медиатеки (`banners/summer.jpg`); в менеджере его выбирают из
медиатеки, в шаблоне — `media()` или `image()` из `$core`.

## Последствия

- Разработчик делает компонент «вставляемым», просто описав его: `<!-- @component -->` и комментарии над
  параметрами. Отдельного реестра блоков нет; компоненты без описания (части шаблонов вроде шапки) в меню
  блоков стоят отдельно, в «Прочих».
- Параметры-объекты, массивы и снипеты в форму не попадают: из текста страницы их не передать.
- Визуальный редактор не портит сложную разметку: такие блоки остаются HTML.
