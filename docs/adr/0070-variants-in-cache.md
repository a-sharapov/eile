# 0070. Варианты картинок из базы — в кэше медиатеки

- Статус: принято
- Дата: 2026-11-09

## Контекст

Варианты размеров (`photo@480/960/1920.webp`) сервер делает сам ([ADR 0046](0046-server-image-variants.md)). У
картинок связанных папок они уже лежат в кэше медиатеки на диске, в базе — только строка
([ADR 0065](0065-linked-folders.md)). У картинок, загруженных в медиатеку, варианты писались в базу кусками, как
файлы. На gabriel.by это 15 МБ из 89 МБ медиатеки в базе: столько лишнего весит каждая копия `cms backup`,
автокопия и копия в хранилище, хотя всё это сервер умеет сделать заново из оригинала.

## Решение

- **Сделанные сервером варианты картинок из базы — в кэше**, как у связанной папки: строка в `media_files` с
  `link = ''` (`CACHE_ONLY`) и `file = NULL`, байты — в кэше до строки. `isDerived()` их узнаёт: отдача из кэша,
  пропавший вариант при старте снимается и картинка встаёт в очередь (`links.heal`), адрес варианта без строки
  ведёт на оригинал 307 без кэша, пока сервер режет.
- **Без кэша на диске** (база в памяти, каталог не пишется) — в базу, как раньше: картинки не остаются без
  вариантов.
- **Свои варианты** (загруженные файлом, присланные `cms media push` из папки темы) — по-прежнему в базе и важнее
  серверных. Свой вариант поверх серверного — можно: строка становится обычной.
- **Старые варианты в базе не трогаются при обновлении**: по строке не отличить сделанный сервером от своего.
  `cms media variants` показывает, где они лежат, `--rebuild` убирает лежащие в базе и ставит картинки в очередь —
  сервер делает их в кэш, база худеет. Свои при этом заменяются серверными; это сказано в справке.

## Последствия

- Копия базы не содержит вариантов: после восстановления на другом сервере они делаются заново (минуты работы
  фона для сотен картинок), до того страницы получают оригинал.
- Удаление картинки убирает её варианты на сервере; менеджер шлёт один запрос.
