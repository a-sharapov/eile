# 0028. HTTPS без прокси: сертификат Let's Encrypt получает сам сервер

- Статус: принято
- Дата: 2026-10-31

## Контекст

Сайт — один бинарник и один файл базы (ADR 0001). Сейчас HTTPS на голом VPS требует nginx или Caddy
перед ним и `--trust-proxy`. Это лишний сервис, его настройка и обновления. Caddy и Traefik давно получают
сертификаты сами. Владелец хочет так же: указать домен — и сайт открывается по HTTPS.

## Решение

**Запуск.** `cms --domain example.com[,www.example.com] [--email you@example.com]`; то же —
`CMS_DOMAIN`, `CMS_ACME_EMAIL`.
- **Два слушателя:** HTTP на `--port` (с доменом по умолчанию 80) и HTTPS на `--https-port` (443,
  `CMS_HTTPS_PORT`).
- **Центр сертификации:** по умолчанию боевой Let's Encrypt. `--acme-staging` — тестовый, `CMS_ACME_DIRECTORY` —
  свой каталог (стенд, тесты).
- **Без `--domain`** всё как раньше.

**HTTP-порт:**
- отдаёт ключи проверки `/.well-known/acme-challenge/<токен>`;
- когда сертификат есть, переадресует остальное на HTTPS ответом 308 (метод и тело сохраняются);
- в адрес переадресации попадают только свои домены: подменённый Host не уводит на чужой сайт;
  _дополнено 2026-11-05: переадресация ведёт на основной домен с любого Host, а HTTPS-порт ведёт туда же
  остальные домены списка ([ADR 0062](0062-primary-domain.md))._
- пока действующего сертификата нет — сразу после первого запуска или если он истёк, — HTTP отдаёт сам
  сайт. Так сайт и ссылка первичной настройки работают с первой минуты, а сбой выпуска (DNS ещё не указывает
  на сервер) не кладёт сайт.

**ACME v2 (RFC 8555) — свой клиент на WebCrypto и fetch,** без пакетов (`certificates/infrastructure`):
- **учётная запись:** ключ ECDSA P-256, подпись JWS ES256 (`jwk` при регистрации, дальше `kid`), согласие с
  условиями;
- **заказ:** авторизации по одной, проверка HTTP-01; опрос с учётом `Retry-After`;
- **запрос сертификата:** PKCS#10 в DER собран вручную, все домены — в subjectAltName, ключ сертификата —
  новый P-256 на каждый выпуск;
- **выпуск:** finalize и загрузка цепочки PEM;
- **ошибки:** `badNonce` повторяется со свежим nonce до трёх раз. Если центр не знает учётную запись
  (`accountDoesNotExist`), заводится новая, один раз. Новая учётная запись сохраняется сразу, чтобы
  неудачные выпуски не плодили их.

**Хранение.** Таблицы `certificates_accounts` (ключ учётной записи у каждого каталога) и
`certificates_issued` (цепочка, ключ, срок, последняя попытка и ошибка). Это данные сервера, а не сайта:
- они в `_SERVER_ONLY`, поэтому в копию сайта не попадают;
- при восстановлении остаются свои: закрытые ключи не путешествуют вместе с сайтом.

**Продление.** `Bun.cron` раз в час, в случайную минуту (Let's Encrypt просит не ходить всем в начале
часа), плюс проверка сразу при старте. Что делать, решает `due()`:
- сертификата нет — выпуск, после неудачи не чаще раза в час (лимит неудачных проверок — 5 в час на домен);
- до конца меньше 30 дней — продление, после неудачи не чаще раза в сутки;
- иначе — ничего.

Неудача — сбой в журнале и уведомление (ADR 0020): без сертификата — critical, при продлении — error, пока
до конца больше недели.

**Подмена без перезапуска.** `server.reload({ tls })` в Bun 1.4.4 сертификат не меняет — проверено. Новый
сертификат поднимает новый HTTPS-слушатель на том же порту с `reusePort`. Старый дорабатывает начатые
запросы и останавливается. Где порт делить нельзя, старый уходит первым — разрыв в миллисекунды.

**Cookie.** Запросы по HTTPS приходят с `https:` в адресе, поэтому cookie входа получает `Secure` и префикс
`__Host-`, как за прокси с `--trust-proxy`.

**Менеджер.** «Настройки → Сайт» показывают блок «HTTPS»: домены, срок, дату выпуска, последнюю ошибку и
пометку о тестовом центре. Блок только для чтения и виден, лишь когда сертификат держит сам сервер
(`GET /manager/api/https`, null иначе).

## Последствия

- На VPS хватает бинарника и DNS: `cms --domain example.com`. Порты 80 и 443 нужны процессу: root,
  `setcap cap_net_bind_service=+ep` или `AmbientCapabilities=CAP_NET_BIND_SERVICE` в systemd (CONTRIBUTING).
- Только HTTP-01: нужен открытый порт 80, сертификатов на `*.example.com` нет (это DNS-01 и API
  регистратора). IP и localhost не принимаются.
- HSTS включён (ADR 0018): ответы HTTPS-слушателя идут с `Strict-Transport-Security: max-age=31536000`, без
  `includeSubDomains` и `preload`. Браузер, хоть раз открывший сайт по HTTPS, год ходит на домен только по
  HTTPS: отказаться от HTTPS на этом домене — значит держать сертификат ещё год. За своим прокси
  (`--trust-proxy`) заголовок ставит прокси.
- Истёкший сертификат при запуске не отдаётся: сайт откроется по HTTP, а сбой будет в журнале.
- Проверено против своего центра на стенде (подписи JWS, nonce, проверка HTTP-01, настоящий X.509 и TLS)
  и через `openssl req -verify`. С боевым Let's Encrypt проверяется на сервере с настоящим DNS.
