# 0069. Основа картинки — одна на оригинал

- Статус: принято
- Дата: 2026-11-09

## Контекст

Варианты размеров называются по основе картинки — пути без расширения: у `img/taxi.jpg` это `img/taxi@480.webp`,
`@960`, `@1920` ([ADR 0046](0046-server-image-variants.md)). `image()` собирает srcset из вариантов основы, очередь решает,
резать ли картинку, по тому, есть ли у основы варианты.

На переезде gabriel.by картинку `taxi.jpg` заменили на `taxi.webp`, а плитки категорий — PNG на JPEG. Новый файл
с той же основой застал варианты прежнего: очередь сочла их «своими вариантами загрузившего» и не резала новый,
а `image()` отдавала srcset старой картинки. Страница показывала прежнее изображение, без ошибки и предупреждения.
SVG с основой PNG (`logo.svg` рядом с `logo.png`) так же получал в srcset чужие варианты. Связанная папка
([ADR 0065](0065-linked-folders.md)) уже обходит это: второй картинке с той же основой даёт `-2`.

## Решение

**У основы — не больше одного оригинала JPEG, PNG или WebP.**

- **Запись в медиатеку** (менеджер, API, MCP, пакеты): новая картинка, чья основа занята другим оригиналом JPEG,
  PNG или WebP, — отказ `media.stem_taken` с именем того файла. Замена файла тем же путём — как была: прежние
  варианты уходят, сервер режет новые. Пара, которая уже лежит в базе, не мешает их обновлять.
- **`image()`** берёт варианты только у JPEG, PNG и WebP: SVG и GIF с той же основой остаются без srcset.
- **`cms media push`**: две картинки папки с одной основой — нарушение правил папки, не пишется ничего. Новая
  картинка папки и картинка медиатеки с той же основой — это замена формата: с `--prune` прежняя уходит вместе
  с вариантами до записи новой, и сервер режет варианты из новой. Без `--prune` или если прежнюю держат страница,
  сайт или элемент — отказ с причиной, не пишется ничего.
- **`--prune`**: вариант, которого нет в папке, остаётся, только пока остаётся его картинка по тому же пути.
  Варианты без картинки и варианты заменённой картинки уходят.
- **`cms import-wp`**: картинки с одной основой (`photo.jpg`, `photo.png`) получают разные пути — вторая `-2`, как в
  связанной папке.

## Почему не варианты на файл

Имя варианта с расширением оригинала (`taxi.jpg@960.webp`) снимает столкновение, но меняет адреса всех вариантов,
формат имени, который знают менеджер, пакеты и папки тем со своими `@960`, и разбор `stemOf()`. Последний
записанный оригинал «побеждает» — тогда srcset прежнего показывал бы новую картинку: то же молчаливое
расхождение, только в другую сторону. Отказ с понятной причиной дешевле и честнее: имя картинки выбирает человек.

## Последствия

- Загрузить `photo.png` рядом с `photo.jpg` нельзя: менеджер объясняет, что сделать, — назвать иначе или заменить.
- Замена формата в папке под git — одной командой `cms media push --prune`.
- Варианты, загруженные раньше оригинала, по-прежнему важнее серверных: правило касается только второго оригинала.
