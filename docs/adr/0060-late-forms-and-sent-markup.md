# 0060. Формы, появившиеся после загрузки, и своя разметка ответа `<template data-sent>`

- Статус: принято
- Дата: 2026-11-05

## Контекст

**Переходы без перезагрузки.** Сайт может менять страницы сам: скачать следующую `fetch`, заменить `<main>`,
`history.pushState`. Регион формы `[#Form:имя]` приходит тогда в новом DOM, а скрипт улучшения форм проходил
`document.querySelectorAll('form[data-cms-form]')` один раз, при загрузке модуля. Форма на второй странице
оставалась без отправки по JSON, ошибок у полей, черновика, шагов и задачи защиты — то есть уходила обычной
отправкой без решения задачи, и сервер просил решить её заново. А на странице, где формы при первой загрузке не
было, скрипта нет вовсе: `<script type="module" src="/_cms/forms/enhance.<хэш>.js">` и стили форм сервер кладёт
в `<head>` только странице с формой.

**Ответ после отправки.** Со скриптом форма заменялась блоком
`<div class="cms-form cms-form-sent" role="status" tabindex="-1"><p>текст</p></div>`, без скрипта сервер после
303 на `?sent=<имя>` рисовал такой же блок. Текст — настройка «спасибо», строкой. Сайтам нужен ответ со своей
разметкой: заголовок, ссылка на каталог, кнопка «Написать в Telegram».

## Решение

### Формы, что появились позже

Скрипт улучшает каждую форму **один раз**, где бы и когда бы она ни появилась:

- `enhance(form)` — всё, что раньше делал цикл: `novalidate`, `min` у дат, черновик, условия, шаги, задача защиты,
  обработчики. Метка улучшенной формы — свойство элемента `Symbol.for('cms:form-enhanced')`. Символ из общего
  реестра один на страницу: если роутер подгрузит скрипт улучшения ещё раз под новым хэшем (после выпуска новой
  версии), вторая копия форму не тронет. Копия формы (`cloneNode`) метки не несёт, как и её обработчиков, и
  улучшается заново. Атрибут вместо символа годился бы хуже: его скопировал бы и `cloneNode`.
- При загрузке модуля — формы, которые уже есть в документе. `DOMContentLoaded` скрипт не ждёт и раньше не ждал:
  модуль выполняется после разбора документа, а загруженный поздно (роутер вставил `<script>` в `<head>`) —
  когда загрузится. Поэтому поздняя загрузка работает так же.
- `MutationObserver` на `document.documentElement` (`childList`, `subtree`): у каждого добавленного элемента —
  он сам, если это форма, и формы внутри. Наблюдатель смотрит только добавленные узлы, атрибутов и текста не
  трогает; страница без форм платит за него перебором добавленных элементов, обычно единиц.

**Что должен сделать роутер сайта.** Страница без формы скрипта форм не загружает, и Eile не может подложить его
заранее: это лишние килобайты всем страницам. Поэтому роутер, который подменяет `<main>`, переносит из `<head>`
скачанной страницы новые `<style data-cms-form>` и `<script type="module" src="/_cms/forms/enhance.….js">`
(скрипт — новым элементом `<script>`, иначе браузер его не выполнит) и, как обычно, `<link rel="stylesheet">`.
Остальное сделает наблюдатель. Модуль с тем же адресом браузер выполняет один раз, поэтому скрипт можно
переносить, не проверяя, был ли он: второй раз он не запустится. Это записано в памятке для моделей
(`GUIDE.form`), README и здесь.

Метки UTM первого касания скрипт по-прежнему берёт из адреса при своей загрузке: после перехода роутером новый
адрес с `utm_*` их не перезапишет — так и задумано («первое касание»).

### Своя разметка ответа

**`<template data-sent>…</template>` в разметке формы** — то, что посетитель увидит после отправки вместо текста
«спасибо». Имя — в духе остальных атрибутов формы (`data-field`, `data-step`, `data-show-if`): `<template>` браузер
не показывает и в `FormData` не берёт, поэтому шаблон лежит в самой форме и ей не мешает.

```html
<template data-sent>
  <h2 tabindex="-1">Спасибо, перезвоним сегодня</h2>
  <p>А пока — <a href="[~12~]">наши кухни</a>.</p>
</template>
```

- **Со скриптом** блок ответа тот же: `div.cms-form.cms-form-sent`, `id` формы, `role="status"`,
  `tabindex="-1"`. Внутри — копия содержимого шаблона (`document.importNode(template.content, true)`), а не
  `<p>` с текстом. Фокус — на первый элемент с `tabindex="-1"` внутри, если он есть, иначе на сам блок, как раньше.
  Берётся первый `template[data-sent]` формы.
- **Без скрипта** после 303 на `?sent=<имя>` сервер рисует тот же блок с содержимым шаблона (`sentOf` в
  `html-markup.ts`), и его же нет — прежний `<p>` с текстом. Порт `FormMarkup.sent` получил исходник формы.
- **Одинаково в обоих путях.** Ссылки `[~id~]` раскрываются, как во всей форме (`linked`); id внутри шаблона
  получают префикс формы (`callback-…`), как остальные id формы: скрипт копирует шаблон из уже нарисованной формы,
  сервер прогоняет его тем же правилом. Поэтому разметка ответа в обоих путях совпадает символ в символ.
- **Шаблон — не поля.** Разбор формы (`_scan`), подсказки полей (`_hintsOf`) и заполнение после ошибки
  (`_filled`) не заходят внутрь `<template>`: поле в шаблоне не попадёт ни в поля формы, ни в проверку, ни в
  заявку, ему не подставят значение и ошибку. Так же поступает браузер. Проверки «есть ли своя кнопка», «есть ли
  файлы», «есть ли шаги» смотрят разметку без шаблонов: кнопка «Отправить ещё» в ответе не убирает кнопку
  отправки. Это правило — для любого `<template>` в форме, не только ответа.
- **Безопасность — как у остальной разметки формы.** Форму пишет администратор с правом `forms.edit`, её HTML
  уходит на страницу как есть (ADR 0021), и шаблон ответа — её часть: новых прав и новой дороги для разметки нет.
  Ответ сервера на JSON-отправку не несёт разметки — скрипт берёт её из формы на странице, а не из ответа.
- **Без шаблона** поведение прежнее; страница «Спасибо» (`successPage`) по-прежнему важнее и шаблона, и текста.

**Редактор форм.** Шаблон на верхнем уровне разметки — неполевой HTML, то есть текстовый блок; визуальному
редактору он не подходит (`fitsVisual`), и блок открывается в режиме HTML. Разбор блоков — DOM браузера:
`outerHTML` у `<template>` вместе с содержимым, сборка возвращает его как был (`tests/form-blocks.test.ts`, и в
Chrome). Под полем «Текст «спасибо»» — подсказка про `<template data-sent>`, в справке менеджера — абзац.

## Проверка

Кроме тестов (разбор, заполнение, `sentOf`, путь без JS через `?sent=`, сборка блоков) — headless Chrome на сервере
из исходников (скрипт стенда в репозиторий не входит): страница без формы → роутер скачивает страницу с формой в
шагах, переносит стили и скрипт из `<head>`, заменяет `<main>` → форма улучшена (`noValidate`), кнопки шагов
собраны один раз; перенос той же формы в другой узел и вторая копия скрипта под другим адресом — кнопок шагов
по-прежнему одни. Отправка — блок ответа с содержимым шаблона, `[~1~]` стал `/`, фокус на заголовке
`callback-done`, заявка в базе. Форма без шаблона, загруженная роутером, — прежний текст, фокус на блоке. Переход роутером со страницы с формой,
где скрипт уже выполнился, на другую страницу с формой — новая форма улучшена. Разбор шаблона менеджером:
`outerHTML` с содержимым; `FormData` формы поле из шаблона не берёт. Тот же стенд со скриптом улучшения из
прежней версии падает на переходе «из формы в форму» (форма не улучшена), на разметке ответа и на второй копии
скрипта (кнопки шагов дважды) — то есть проверяет именно то, что изменилось.

## Последствия

- Сайты с переходами без перезагрузки получают рабочие формы, если их роутер переносит новые теги из `<head>`.
- Ответ после отправки можно сверстать как угодно, не заводя страницу «Спасибо», и без скрипта он тот же.
- Скрипт форм держит один `MutationObserver` на документ — на всех страницах, где он загружен.
- Поле, положенное внутрь `<template>`, перестало считаться полем формы. Раньше сервер видел его, а браузер не
  присылал: такое поле с `required` делало форму неотправляемой. Теперь сервер и браузер согласны.
