# 0051. Почта через HTTP API: Brevo, Postmark, Mailgun, Resend, Amazon SES

- Статус: принято
- Дата: 2026-11-03

## Контекст

Почта Eile уходит только по SMTP (ADR 0020): уведомления, письма посетителям, проверка канала и почтовый
шлюз (ADR 0040). Многие VPS закрывают исходящий SMTP. У новых аккаунтов DigitalOcean, по отзывам, закрыты
25, 465 и 587, Hetzner для новых клиентов закрывает 25 и 465. На таком сервере письма не уходят: SMTP-клиент
упирается в срок подключения, очередь повторяет и сдаётся, шлюз отвечает `502`. Из-за этого стоит запуск
живого сайта на дроплете DigitalOcean.

Порт 443 открыт: через него ходит сам сайт. Почтовые сервисы принимают письма по HTTPS: у каждого своё
API, ключ и правила подтверждения отправителя. SDK не берём: бинарник обходится без зависимостей, кроме
`svelte`, а запросы этих API — один `POST` с JSON или формой.

## Решение

**Способ отправки — часть настроек почты.** `EmailSettings` стал объединением по полю `transport`:
`smtp` (как раньше: сервер, порт, шифрование, логин, пароль) или один из пяти сервисов (`MailProvider`).
Отправитель и адресаты общие. У сервиса вместо сервера и пароля — ключ и поля, без которых он не отправит.
Почта, сохранённая прежней версией, без `transport`, читается как SMTP (`storedSettings`), миграции нет.
Всё, что шлёт почту, идёт через `EmailSender`, а он выбирает отправителя по `transport`
(`defineEmailSender`). Поэтому сервис получают уведомления, письма посетителям, ссылки сброса пароля,
проверка канала, письма шлюза и его проверка связи (`?probe=1`).

| Сервис     | Поля                                                                                     | Запрос                                                                                                                            | Ключ                                      |
| ---------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Brevo      | ключ API                                                                                 | `POST https://api.brevo.com/v3/smtp/email`, JSON                                                                                  | `api-key`; ключ SMTP `xsmtpsib-…` — отказ |
| Postmark   | токен сервера, поток (`outbound` по умолчанию)                                           | `POST https://api.postmarkapp.com/email`, JSON                                                                                    | `X-Postmark-Server-Token`                 |
| Mailgun    | ключ API (или ключ отправки домена), регион `us`/`eu`, домен (пусто — домен отправителя) | `POST https://api[.eu].mailgun.net/v3/<домен>/messages.mime`, `multipart/form-data`: `to` по адресату и `message` — письмо MIME   | Basic `api:<ключ>`                        |
| Resend     | ключ API (`re_…`)                                                                        | `POST https://api.resend.com/emails`, JSON                                                                                        | `Authorization: Bearer`                   |
| Amazon SES | регион, идентификатор ключа доступа (`AKIA…`), секретный ключ                            | `POST https://email.<регион>.amazonaws.com/v2/email/outbound-emails`, JSON: `FromEmailAddress`, `Destination`, `Content.Raw.Data` | подпись SigV4, сервис `ses`               |

Адреса API зашиты в код, в настройках их нет: ключ уходит только на адрес сервиса. Переадресации запрещены
(`redirect: 'error'`). Иначе Brevo с его заголовком `api-key` унёс бы ключ на чужой адрес.

**Письмо MIME, где сервис его принимает.** SES (`Raw`) и Mailgun (`messages.mime`) получают те же байты,
что ушли бы по SMTP: `mimeMessage` для уведомлений, `mailParts` для шлюза. Заголовки, `multipart/related` с
картинками по `cid`, `Sender` у письма с разрешённым отправителем, `Reply-To` посетителя — всё на месте.
Конверт — как `MAIL FROM` и `RCPT TO`: у SES это `FromEmailAddress` и `Destination.ToAddresses`, у Mailgun —
поля `to`. Brevo, Postmark и Resend письмо MIME не принимают и собирают его сами из полей JSON. Что при этом
теряется:

| Сервис   | Как в JSON                                                                                                                                       | Что теряется                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Brevo    | `sender {name, email}` (имя до 70 знаков), `to [{email}]`, `replyTo`, `htmlContent`, `textContent`, `attachment [{name, content}]`               | Картинок по `cid` у API нет: они уходят обычными вложениями, `<img src="cid:…">` в письме не покажется. Brevo принимает вложения только с расширениями из своего списка |
| Postmark | `From`, `To` через запятую, `ReplyTo`, `HtmlBody`, `TextBody`, `MessageStream`, `Attachments [{Name, Content, ContentType, ContentID: "cid:…"}]` | —                                                                                                                                                                       |
| Resend   | `from`, `to []`, `reply_to`, `html`, `text`, `attachments [{filename, content, content_type, content_id}]`                                       | —                                                                                                                                                                       |

У всех трёх `Message-ID`, `Date` и конверт ставит сервис. Заголовка `Sender` нет: если в `From` другой
разрешённый адрес шлюза, сервис должен знать и его (подтверждённый домен). Имя в `From` простое, как в
примерах сервисов (`Mühlenhof <site@muehlenhof.example>`), с запятой, точкой или кавычками — в кавычках. Текст и
HTML, как и в письме SMTP, всегда оба: недостающее собирается из другого (`plainOf`, `htmlOf`). Своих
заголовков шлюз не передаёт и сейчас (ADR 0040), так что от них нечего терять.

**Ошибки сводятся к причине.** Ответ сервиса с ошибкой разбирается его же словами (Brevo
`code`/`message`, Postmark `ErrorCode`/`Message`, Resend `name`/`message`, SES `x-amzn-ErrorType` или
`__type`) и сводится к одной причине из десяти. От причины зависят текст и то, будут ли повторы. Текст
сервиса идёт следом в скобках, не длиннее 300 знаков. Ключ из текста вырезается, даже если сервис его
повторил.

| Причина                    | Когда                                                                                                                                                           | Повтор                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| ключ не принят             | 401/403, Postmark `ErrorCode 10`, SES `UnrecognizedClientException`, `InvalidSignatureException` и т. п.                                                        | нет                                                                       |
| IP сервера не разрешён     | Brevo 401 про IP («Authorized IPs»), Postmark `1480`                                                                                                            | нет                                                                       |
| отправитель не подтверждён | Brevo 400 про sender, Postmark `400`/`401`/«Sender Signature», Resend 403 про домен, SES `MessageRejected … not verified`, `MailFromDomainNotVerifiedException` | нет                                                                       |
| домен не найден в регионе  | Mailgun 404                                                                                                                                                     | нет                                                                       |
| письмо слишком большое     | 413, SES `MessageRejected` о размере                                                                                                                            | нет                                                                       |
| аккаунт не может слать     | Brevo 402 и `account_under_validation`, Postmark `412`/`413`, Mailgun «not allowed to send», SES `AccountSuspendedException`, `SendingPausedException`          | нет                                                                       |
| просит слать медленнее     | 429, SES `TooManyRequestsException`                                                                                                                             | да, пауза из `Retry-After`, `x-sib-ratelimit-reset` или `ratelimit-reset` |
| квота исчерпана            | Resend `daily_quota_exceeded`/`monthly_quota_exceeded`, SES `LimitExceededException`                                                                            | да                                                                        |
| сервис недоступен          | 5xx, сеть, 30 секунд без ответа                                                                                                                                 | да                                                                        |
| письмо отклонено           | остальные 4xx                                                                                                                                                   | нет                                                                       |

Отказ «насовсем» и «на время» — тот же `SendFailure`, что у SMTP. Поэтому очередь повторяет с тем же
расписанием (минута, 5 и 30 минут, 2 и 12 часов), а исчерпанные попытки — тот же сбой «не доставлено».
Пауза сервиса — не меньше шага расписания и не больше суток. Ошибка TLS — насовсем, как у SMTP: сертификат
сервиса сам не сменится. Шлюз отвечает тем же контрактом `{ok, error}`: отказ сервиса — `502 send_failed`,
причина — в журнале сбоев без адресов. Коды `smtp_not_ready` и проверка `checks.smtp` сохранили имена ради
клиентов PHP-релея, теперь они значат «почта не настроена». Срок запроса — 30 секунд
(`AbortSignal.timeout`).

**Проверка связи** (`?probe=1` шлюза) — `GET` на адрес API без ключа, 8 секунд. Любой ответ HTTP значит, что
сервис достижим. Это как приветствие SMTP без входа; коды те же: `timeout`, `tls_failed`, `connect_failed`.

**Подпись SigV4 — своя.** `sigv4.ts` строит канонический запрос (метод, путь по сегментам, параметры по
ключу и значению в кодировке RFC 3986, заголовки строчными без лишних пробелов, хэш тела), строку для
подписи и HMAC-SHA256 ключом, выведенным из секрета, дня, региона и сервиса (`Bun.CryptoHasher`). Проверена
официальным набором тестов AWS (`awslabs/aws-c-auth`, `tests/aws-signing-test-suite/v4`: 15 случаев — GET и
POST, порядок и кодировка параметров, UTF-8 в пути и запросе, обрезка значений заголовков, тело формы,
токен сеанса) и двумя примерами из документации AWS (вывод ключа и запрос `ListUsers` к IAM). Временные
ключи (`ASIA…`) настройки не принимают: им нужен токен сеанса, а живут они часы.

**Ключи — только на сервере.** Ключ лежит в `notify_settings` рядом с паролем SMTP. Эта таблица — настройка
сервера (`_SERVER_ONLY`, ADR 0045): в копию сайта она не входит, а в файл настроек сервера входит. Менеджер
получает `EmailStatus`, где поля перечислены явно: провайдер, регион, домен, поток, идентификатор ключа SES
и `keyHint` — последние четыре знака ключа. Строка состояния в менеджере: «Письма уходят через Postmark (HTTP
API), ключ …4e5f». Пустой ключ при сохранении — прежний, но только для того же сервиса, региона и ключа
доступа SES: в другой сервис или регион прежний ключ не уходит. Пароль SMTP не переходит к сервису, ключ
сервиса не переходит к SMTP. Документ состояния шлюза ни ключа, ни провайдера не показывает.

**Память** (ADR 0043). Тело запроса собирается в два прохода и целиком в памяти не лежит. Первый проход
считает длину для `Content-Length`, у SES ещё и SHA-256 для подписи. Второй отдаёт тело потоком порциями по
256 КиБ, по мере того как `fetch` их забирает. Проверено: Bun шлёт такой поток с `Content-Length`, без
chunked. base64 вложений пишется из байтов блоками по 48 КиБ, кратными трём байтам, без строки base64 файла
целиком; у SES так же кодируется письмо MIME в `Raw.Data`. Строки JSON целиком нет. Замер: письмо с 13
вложениями по 2 МБ (26 МБ, как письмо шлюза на 36 МБ JSON) отдельным процессом на поддельный сервис, пик
`maxRSS` сверх начального. Brevo — +47…51 МБ за 44–49 мс, Mailgun — +67 МБ за 78–87 мс, SES — +73…76 МБ за
133–148 мс. Первый вариант, с телом одним буфером, давал +80, +111 и +150 МБ. Остаток — недолговечные строки base64 блоков и
два прохода по письму MIME; после ответа шлюз, как и раньше, собирает мусор (`Bun.gc(true)` после тел от 4
МБ).

**Менеджер.** В разделе почты есть выбор «Как отправлять»: свой сервер SMTP или сервис с HTTP API. Подсказка
объясняет, зачем это: хостинг закрыл порты SMTP, а API работает через порт 443. Под выбранным сервисом —
его поля и подсказка, где взять ключ. Ниже — напоминание подтвердить домен отправителя у сервиса записями
SPF и DKIM. Кнопка «Отправить проверку» шлёт письмо через выбранный способ. Тексты — на русском, английском
и немецком.

## Подтверждение отправителя у сервисов

| Сервис     | Что подтвердить                                                                                                                        |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Brevo      | Отправителя или домен (Senders, Domains): записи DKIM и DMARC, код Brevo в TXT. Ключ API и, если включено, IP сервера в Authorized IPs |
| Postmark   | Sender Signature на адрес или домен: DKIM и Return-Path (CNAME). Пока аккаунт на проверке — письма только на свой домен                |
| Mailgun    | Домен отправки (лучше поддомен `mg.`): SPF, DKIM, MX и CNAME отслеживания; регион домена — US или EU                                   |
| Resend     | Домен: SPF и DKIM (TXT, MX на поддомене `send.`). Без домена — только тестовые письма на свой адрес                                    |
| Amazon SES | Удостоверение (identity) домена с Easy DKIM (три CNAME), по желанию — свой MAIL FROM. В «песочнице» — только на подтверждённые адреса  |

Точные записи показывает сам сервис, таблица — для ориентира. Адрес отправителя почты и все разрешённые
отправители шлюза должны лежать в подтверждённом домене.

## Что не проверено

- **Настоящие сервисы.** Ключей нет, поэтому каждый сервис в тестах изображает `Bun.serve`
  (`mail-api.test.ts`, `tests/mail-api.test.ts`). Форма запросов, заголовки ключей и тексты ошибок взяты из
  публичной документации сервисов на 2026-11-03: Brevo `sendTransacEmail` и «How it works» (коды, `x-sib-ratelimit-*`),
  Postmark Email API и коды ошибок API, Mailgun `POST /v3/{domain}/messages.mime`, Resend `POST /emails` и
  справочник ошибок, SES v2 `SendEmail`. Чего в документации нет, решено по известному поведению. Это `content_id` у
  Resend (из журнала изменений Resend, в справочнике API поля нет), коды `400`/`401` о подписи отправителя у
  Postmark (их текущая таблица не перечисляет, поэтому сверяется и текст «Sender Signature»), тело `401
  Forbidden` у Mailgun (часто текстом, не JSON). Первое настоящее письмо через каждый сервис —
  проверка при запуске.
- **Права IAM для SES.** Подсказка просит `ses:SendEmail` и `ses:SendRawEmail`. Какое из них SES v2 требует
  для `Raw`, по документации однозначно не ясно.
- **Заголовок `Sender` у SES.** SES проверяет подтверждение адреса в `FromEmailAddress` (почта сайта).
  Требует ли он подтверждения и адреса из `From` письма, когда там разрешённый отправитель шлюза, не
  проверено. Безопасно держать оба в одном подтверждённом домене.

## Что не сделано и почему

- **Свой адрес API в настройках** (прокси, совместимые сервисы вроде Scaleway TEM). С ним ключ можно было бы
  увести на чужой адрес настройкой. Пять сервисов покрывают задачу, а адреса в коде проще проверить.
- **Ключ идемпотентности** (`Idempotency-Key` у Resend и Brevo). После таймаута письмо могло дойти, и повтор
  очереди пришлёт его второй раз. Так же ведёт себя и SMTP, а ключу нужен id строки очереди внутри
  `EmailSender`.
- **Временные ключи AWS и роли инстанса.** На VPS вне AWS их нет.
- **Другие сервисы** (SendGrid, SparkPost, Mailjet). Добавляются строкой таблицы `PROVIDERS`: адрес, запрос,
  разбор ошибки.

## Последствия

- Сервер без исходящего SMTP шлёт почту: достаточно выбрать сервис и вставить ключ. Порт 443 нужен и самому
  сайту.
- `EmailSender` параметризован настройками: `EmailSender<SmtpEmailSettings>` у SMTP-клиента,
  `EmailSender<ApiEmailSettings>` у `defineApiSender`, общий — у `defineEmailSender`. Подмены в тестах
  реализуют общий. Тесты могут направить настоящий отправитель на поддельный сервис:
  `defineApiSender({ endpoints })`.
- `NotifyStatus.email` — объединение по `transport`. Код, который читал `email.host`, сначала смотрит
  `transport`.
- Файл настроек сервера переносит и ключ сервиса. `cms backup --server` пишет, через что уходит почта:
  «почта (Postmark)».
- Файл настроек сервера с почтой через сервис прежняя версия не поймёт: она прочтёт почту как SMTP без
  сервера. Переезжать с ним — на эту версию или новее.
