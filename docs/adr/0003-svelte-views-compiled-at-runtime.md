# 0003. Шаблоны и компоненты компилируются из базы во время работы

- Статус: принято
- Дата: 2026-10-29

## Контекст

Главное удобство Evo — правка элемента в менеджере сразу видна на сайте. Элементы CMS — Svelte-компоненты,
а Svelte требует компиляции. Плюс всё должно работать внутри одного бинарника, где нет `node_modules`.

## Решение

- Исходник хранится в `design_elements`. При сохранении он компилируется для проверки, ошибка отклоняет
  сохранение.
- При рендере загрузчик видов (`defineViewLoader`):
  1. компилирует элемент через `svelte/compiler` (`generate: "server"`, `css: "injected"`, `runes: true`);
  2. проверяет импорты (`Bun.Transpiler.scanImports`): разрешены только `$components/*`, `svelte`,
     `svelte/internal/server` и `$core`;
  3. переписывает импорты на виртуальные спецификаторы `@cms/views-N/…`. У компонентов в спецификаторе
     хэш итогового кода, поэтому изменение зависимости меняет спецификаторы всех зависящих от неё элементов;
  4. регистрирует модули через `Bun.plugin` → `build.module()`. Хост-модули отдаются как
     `loader: "object"`;
  5. загружает шаблон через `import()` с вычисляемым спецификатором.
- Публичные страницы рендерятся своим конвейером (`svelte/server` `render()`), а не роутингом SvelteKit:
  роутинг и Vite работают на этапе сборки, а элементы живут в базе. SvelteKit остаётся для SPA менеджера.
- По умолчанию на клиент не уходит JS, маркеры гидрации из HTML удаляются.

## Проверено (Bun 1.4.4, Svelte 5.57.3, 2026-10-29)

| Факт                                                                                                                                    | Следствие                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `build.module()` работает и после `setup`, в `bun run`, `bun test` и в бинарнике `--compile`                                            | Основа загрузчика                                                                                             |
| Рантайм-`onResolve` не видит голые спецификаторы («Cannot find package»)                                                                | Не используем                                                                                                 |
| `import("литерал")` бандлер пытается разрешить при сборке, и сборка падает                                                              | Спецификатор всегда вычисляемый                                                                               |
| ESM-кэш отдаёт старый модуль по тому же спецификатору                                                                                   | Хэш содержимого в спецификаторе                                                                               |
| `bun test` ставит `NODE_ENV=test`, тогда `esm-env` даёт `DEV = true`, и Svelte добавляет лишние маркеры (`<!--hash-->` перед `{@html}`) | Тесты запускаются с `NODE_ENV=production`, бинарник собирается с `--define process.env.NODE_ENV="production"` |
| Компиляция: первая около 20 мс (прогрев), дальше около 2 мс; рендер около 0,07 мс                                                       | Компилируем при промахе, не на каждый запрос                                                                  |

## Последствия

- Загруженные модули не выгружаются: каждая правка добавляет модуль в память процесса. Для правок из менеджера
  это допустимо, перезапуск освобождает память.
- Импорты переписываются регулярным выражением по скомпилированному коду. Svelte выдаёт стабильный формат
  `import … from '…'`, а покрывают это тесты.
- Компоненты работают только на сервере и синхронно берут данные через `$core`. Клиентские острова —
  отдельный этап ([roadmap](../roadmap.md)).

## Отклонённые варианты

- **Компиляция при сборке** (как в SvelteKit) теряет правку без деплоя.
- **`eval` / `new Function`** требуют своего загрузчика ESM и обходят модульную систему Bun.
- **Запись модулей во временные файлы** не работает внутри бинарника: модулям нечем разрешать `svelte`.
