# 0022. Каркасы сайтов и приветствие вместо демо-сайта

- Статус: принято
- Дата: 2026-10-31

## Контекст

До сих пор первый запуск наполнял пустую базу демо-сайтом: три страницы, блог, шаблон Base, компоненты
Header и Callout. Демо показывало, что всё работает, но мешало: настоящий сайт начинался с удаления чужих
страниц и элементов. При этом пустой сайт без единого шаблона тоже неудобен: страницу не создать, пока нет
шаблона.

Evo решал это так. Установщик ставит Minimal Template и страницу «Install Success», а по галочке — демо-сайт
целиком (`install/setup.data.sql`). Владелец хочет так же: по умолчанию почти пусто, а готовые сайты для
типовых задач — одной командой.

## Решение

**Приветствие по умолчанию.** На пустой базе сервер создаёт одну страницу «Добро пожаловать» и пустой
шаблон Minimal: заголовок вкладки и `{@html page.content}`. Название сайта — название программы.

**Каркас — данные.** `Scaffold` (`src/scaffolds/scaffold.ts`) описывает сайт целиком:
- компоненты набора (их зависимости ставятся сами) и свои компоненты;
- шаблоны, поля, формы и свои настройки;
- дерево страниц, ключи главной и 404.

Один интерпретатор `applyScaffold` ставит всё это через публичные API контекстов, как сделал бы человек в
менеджере. Отдельного хранилища у каркаса нет. После развёртывания это обычные страницы и элементы сайта, их
правят как свой код.

**Ссылки внутри каркаса — ключи.** Id страниц заранее неизвестны, поэтому страница каркаса может иметь `key`.
- `@{key}` в тексте страниц, исходнике форм и своих настройках становится id:
  - `[~@{contacts}~]` — ссылка на страницу;
  - `[[PostList parent=@{blog}]]` — параметр компонента;
  - настройка `cart = @{cart}` — id страницы корзины для шаблона.
- Текст и формы пишутся вторым проходом, когда известны id всех страниц.

**Каркасы:** блог, портфолио, сайт компании, витрина, интернет-магазин (`SCAFFOLDS`).
- Каждый — своя рамка-компонент Layout со своими цветами и шрифтами. Переменные `--t-*` подхватывают
  компоненты набора и формы.
- Внешних шрифтов и запросов нет. Картинок в бинарнике тоже нет: пока поле обложки пустое, вместо неё рисуется
  заготовка из CSS.
- Магазин принимает заказ без онлайн-оплаты:
  - корзина — острова на `localStorage`;
  - заказ — заявка формы `order`, состав заказа корзина пишет в её поле;
  - статусы и уведомления — те же, что у заявок (ADR 0020, 0021).

**Команда `cms new <каркас>`.**
- Создаёт базу или берёт существующую, если на ней пусто или лежит нетронутое приветствие.
- «Нетронутое» значит:
  - страницы приветствия и элементы совпадают с исходными;
  - полей и форм нет.
- Приветствие удаляется, пользователи остаются: администратор, созданный по ссылке настройки, не теряется.
- На сайт со своей работой каркас не ложится.
- `--name` задаёт название сайта.

**Демо-сайт ушёл в тесты** (`tests/fixtures/demo.ts`) и записан тем же форматом `Scaffold`. Тесты проверяют
формат на всех страницах, а программа не возит в себе сайт, который никто не запускает.

## Последствия

- Новый сайт начинается чисто, а типовой — за одну команду, без ручной вёрстки с нуля.
- Каркасы растят бинарник на исходники `.svelte` и тексты — десятки килобайт.
- Каркас — это стартовая точка, а не тема: обновление программы не трогает уже развёрнутые элементы.
- Применять каркас на работающем сервере из командной строки нельзя: кэши сервера о нём не узнают. Сервер
  перезапускают после команды.
