# 0032. Полоса правки на сайте: только вошедшим, мимо кэша, редактор менеджера в окне

- Статус: принято
- Дата: 2026-10-31

## Контекст

В Evo с сайтом идёт QuickManager: вошедший в менеджер видит на страницах полосу с id, «Редактировать»,
«Создать здесь», «Менеджер» и «Выйти». «Редактировать» открывает форму менеджера в окне поверх
страницы, после сохранения окно закрывается и страница перезагружается (`docs/evo-essence.md`). Людям
из Evo этого не хватало: найти страницу в дереве, чтобы поправить опечатку, которую видно прямо на сайте,
— лишний круг. При этом сайт Eile отдаёт страницы из общего кэша, и посетитель не должен получить ни
байта лишнего, а чужой человек — полосу.

## Решение

**Полосу вставляет сервер и только тому, кто вошёл.**
- Отдача страницы знает, чью страницу показала (`Delivery.pageId`, в кэше — тоже). Для HTML-страницы
  с id обработчик сайта спрашивает порт `EditBar` (его даёт корень из контекста `manager`).
- Контекст `manager` проверяет cookie сеанса тем же `identity.authenticate`, что и API. Нет сеанса — null,
  и посетитель получает ровно ту же страницу, ETag и сжатую копию из кэша.
- Есть сеанс — полоса вставляется перед последним `</body>` уже после кэша. Такой ответ —
  `Cache-Control: private, no-store`, `Vary: cookie`, без ETag; в общий кэш он не попадает.
- Страницы-файлы (CSS, лента, SVG) и голый 404 без своей страницы полосу не получают.

**Скрипт — отдельный файл, настройки — в странице.** В страницу идут `<script type="application/json">`
с id страницы, правами, акцентом и текстами и `<script src="/manager/bar.<хэш>.js" defer>`. Скрипт —
`edit-bar.client.js`, вшитый текстом, как улучшение форм; адрес с хэшем кэшируется навсегда. Внешний
файл, а не встроенный скрипт: CSP шаблона с `script-src 'self'` его не заблокирует.

**Полоса не мешает сайту и сайт ей.**
- Разметка — в теневом DOM элемента `<eile-bar>`: стили сайта её не задевают, её стили не вытекают.
- Своя тёмная палитра, размеры в px, системный шрифт; из оформления пользователя — только акцент.
- Страница сдвигается вниз на высоту полосы (`html { margin-top }`), а не прячет шапку сайта под ней.
- «Скрыть» сворачивает полосу в значок в углу; выбор помнится в браузере.
- Внутри фрейма (предпросмотр, чужое встраивание) полоса не рисуется.

**Редактор — сам менеджер во фрейме.**
- «Редактировать» и «Вложенная страница» открывают `dialog` с `/manager/pages/<id>?embed` и
  `/manager/pages/new?parent=<id>&embed`.
- Менеджер с `?embed` разрешает встраивание только своему сайту (`frame-ancestors 'self'`,
  `X-Frame-Options: SAMEORIGIN`); без него — `'none'` и `DENY`, как раньше.
- Во фрейме менеджер рисует одну холстину, без шапки и дерева (`lib/embed.ts`).
- Редактор сообщает странице `postMessage` своего источника: есть ли несохранённое и что сохранено.
- Закрытие с правками спрашивает. Сохранение закрывает окно; страница перезагружается, а новая
  опубликованная — открывается.
- Фрейм создаётся на открытие и удаляется на закрытие: так он не переспрашивает о несохранённом сам.

**Тексты полосы — на языке пользователя** (его выбор в оформлении, иначе `Accept-Language`), как и всё,
что сервер собирает для менеджера (ADR 0031).

## Последствия

- Вошедший в менеджер видит страницы сайта не из кэша браузера и CDN: ответ личный. На скорость для
  посетителей это не влияет.
- Новая кнопка полосы — строка в `_TEXTS` (три языка) и в скрипте. Права — по ролям identity:
  `content.edit` открывает правку.
- «Выйти» с полосы, как в Evo, не сделан: посмотреть сайт глазами посетителя можно, свернув полосу.
