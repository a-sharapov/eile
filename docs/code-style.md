# Стиль кода

Обязателен для `src/` и `tests/`. Чеклист перед сдачей диффа — скилл `cms-conventions`. Решение и
причины — [ADR 0006](adr/0006-functional-style.md).

## Форматирование

Biome (`biome.json`): 2 пробела, 80 колонок, одинарные кавычки, точки с запятой, trailing commas `es5`.
Импорты сортирует Biome. `bun run format` форматирует, `bun run lint` проверяет.

## Модули

- Экспорт — `export var name = (…) => …`. Не `const` и не `function` (исключение — генераторы
  `function*`).
- Приватное в модуле — `const _name`. Константы — `_UPPER_CASE` (приватные) и `export var UPPER_CASE`.
- Типы — `type`, а не `interface`. Типы импортируются через `import type`.
- Классов нет. Состояние, которое нужно хранить (кэш, подписки), живёт в замыкании фабрики `define*`
  (`let` внутри функции).

## `pipe` и `reduce`

- Если над значением выполняется два шага или больше, это `pipe(a, b, c)(x)` из `shared/kernel/pipe.ts`.
  Шаг, который вернул Promise, переводит остаток цепочки на `.then`. `null`, `0` и `''` передаются дальше как
  значения.
- Шаг — одно преобразование без мутации. Лямбда с одним параметром пишется как `(_) => …`. Имя параметра
  даётся, только если он используется больше одного раза или без имени шаг читается хуже.
- Шаги называют глаголами: `assertAliasFree`, `rewrite`, `register`. В `pipe` они читаются сверху вниз
  как сценарий.
- Накопление — `reduce` с неизменяемым аккумулятором (`{ ...acc, [key]: value }`, `[...acc, x]`), а не
  `for` с мутацией.
- Побочный эффект ставится на краю цепочки или пишется шагом `(_) => (effect(_), _)`.

```ts
const store = pipe<PageChange, PageId>(
  assertAliasFree,
  (_: PageChange) => (pages.save(_.state), _),
  (_: PageChange) => (_.events.forEach(bus.publish), _.state.id)
);
```

## Без early return

- Никаких `if (…) return`. Ветку выражают тернарником, `??`, `?.` или `void (cond && effect())`.
- Нарушенное правило внутри выражения — `fail(code, message)` из `shared/kernel/errors.ts`:
  `valid ? value : fail('content.invalid_alias', '…')`.
- Можно несколько `const` и один `return` в конце, если так читается проще вложенного выражения.

## Таблица вместо `if`

Если значение выбирается по дискретному ключу (kind, метод, область), это `Record` и `map[key] ?? map._`,
а не цепочка `if` / тернарников. Примеры в коде: `_RESPONSES[result.kind]` в
`delivery/interface/site-handler.ts`, `_EDIT[key]` в `content/domain/page.ts`.

## Promise

- Асинхронные цепочки пишутся как `.then(_handle, _catch)` с именованными шагами, а не через
  `async`/`await` с `try`/`catch`.
- Код, который может бросить синхронно, заворачивается в `Promise.resolve(x).then(step)`, чтобы ошибка
  стала отказом Promise (см. `views.template`, `delivery.deliver`).
- `async`/`await` допустим только в тестах.

## Кортежи

Деструктуризация по индексам: `const { 0: key, 1: value } = entry` и `({ 1: value }) => …` в колбэках.
Пропусков вида `[, value]` не используем.

## DDD в функциональном стиле

- **Агрегат** — неизменяемый `type` (`Page`, `Element`).
- **Переход** — чистая функция `(state) => Changed<State, Event>`: `changed(next, ...events)` из
  `shared/kernel/changed.ts`. Если ничего не изменилось, возвращается `changed(state)` без событий.
  Переходы сцепляет `chain(next)(previous)`, события при этом копятся.
- Создание — `createX(id, input)`, правка — `editX(changes)(state)`, смена статуса — `publishX(state)`.
- **Объект-значение** — `Brand<T, 'Name'>` плюс `parseX(raw)`.
- **Ошибка домена** — `fail('context.reason', 'English message')`; распознать её помогает
  `isDomainError(error)`.
- **Репозиторий** — тип-порт в `domain/` и `defineXRepository(db)` в `infrastructure/`. SQL-запросы
  готовятся один раз, в фабрике.
- **Сервис** — `defineXService(ports)` в `application/`. Принимает порты (в тестах их подменяют) и
  возвращает операции по пространствам имён: `content.pages.create`, `design.components.save`,
  `site.settings.update`.
- **Контекст** — `defineX({ db, bus, … })` в `index.ts`: создаёт адаптеры и отдаёт сервис. Экземпляры
  создаёт только корень композиции `src/app.ts`. Готовых синглтонов модули не экспортируют: в одном процессе
  может жить несколько сайтов, а тестам нужны изолированные приложения.

## Комментарии

- По умолчанию кода без комментариев. Комментарий пишут, когда без него читатель не поймёт код или сломает
  его: неочевидное «почему», единицы, источник числа, обход бага библиотеки, внешний контракт, директива
  инструмента с причиной. Это одна-две строки по-русски.
- Нельзя: пересказ кода, история изменений, ссылки на этапы и задачи, разделители, закомментированный код,
  TODO без задачи.
- JSDoc у экспорта — одна строка и только тогда, когда контракт не ясен из имени и типов.

## Язык

- Идентификаторы — на английском. Комментарии и документация — на русском. Тексты ошибок (`fail`) и логов —
  на английском.
- Названия тестов — на русском: `it('страница находится по пути из алиасов', …)`.

## CSS (демо, менеджер)

Размеры — `rem`/`em`, не `px`. Во внешних CSS нет `:global()`. Иконки в кнопках — только SVG.

## Проверка

`bun run check` = lint + typecheck + test.
