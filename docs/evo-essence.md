# Суть Evo

Выжимка из исходников Evolution CMS 1.4.37 (`evolution-1.4.37/`, в git не входит). Документ описывает
**поведение** своими словами. Код Evo под GPL-3 не копируется и не переводится построчно
([ADR 0004](adr/0004-clean-room-from-evo.md)).

Почти всё ядро — один класс `DocumentParser` в `app/includes/document.parser.class.inc.php` (~7200 строк).
Номера строк ниже указаны для 1.4.37.

## Модель данных

Схема — `install/setup.sql`.

## Конвейер запроса

1. `executeParser()` (`:2814`) загружает настройки, `prepareResponse()` (`:2993`) находит ресурс по URL.
2. **Кэш.** `getDocumentObjectFromCache()` (`:858`) ищет файл `assets/cache/docid_<ключ>.pageCache.php`
   (`getHashFile()`, `:823`). Ключ — id документа, а при `cache_type = 2` — id плюс хэш GET-параметров
   (`makePageCacheKey()`, `:832`).
3. **Сборка**, если кэша нет: шаблон плюс поля документа идут в `parseDocumentSource()` (`:2762`). Это
   **многопроходный** парсер. Каждый проход:
   - событие `OnParseDocument`;
   - при `enable_at_syntax`: комментарии `<!--@- -@-->` и условия `<@IF:…>` (`:1734`, `:1888`);
   - `[(setting)]` → `mergeSettingsContent()` (`:1556`);
   - `[*field*]` → `mergeDocumentContent()` (`:1364`);
   - `{{chunk}}` → `mergeChunkContent()` (`:1605`);
   - `[[snippet]]` → `evalSnippets()` (`:2060`), выполнение PHP через `evalSnippet()` (`:2012`);
   - `[+placeholder+]` → `mergePlaceholderContent()` (`:1674`).

   Проходов минимум 2, и они повторяются, пока результат меняется, но не больше 10.
4. **Запись в кэш** — `postProcess()` (`:1211`). Кэшируется только опубликованный документ с `cacheable = 1`.
   В файл попадают сериализованный объект документа и HTML, в котором **некэшируемые вызовы `[!snippet!]`
   оставлены как есть**.
5. **Вывод** — `outputContent()` (`:960`). Если в HTML остались `[!…!]`, они превращаются в `[[…]]` и
   парсятся **на каждом запросе** (`:974`). Затем вставляются зарегистрированные скрипты, `[~id~]` заменяются
   на URL (`rewriteUrls()`, `:2515`), вызываются `OnWebPagePrerender` и `OnWebPageComplete`.

**Главный приём скорости Evo — двухфазный рендер:** страница целиком лежит в кэше, а динамические места
дорисовываются при каждом запросе. Это берём обязательно.

## Теги

| Тег                        | Что делает                                            |
| -------------------------- | ----------------------------------------------------- |
| `[*field*]`                | Поле текущего документа или TV                        |
| `[(name)]`                 | Системная настройка                                   |
| `{{name}}`                 | Чанк                                                  |
| `[[Name? &param=`value`]]` | Сниппет, результат кэшируется вместе со страницей     |
| `[!Name!]`                 | Сниппет без кэша, выполняется на каждом запросе       |
| `[+name+]`                 | Плейсхолдер, который выставил сниппет или вызов чанка |
| `[~id~]`                   | URL документа (`makeUrl()`, `:4260`)                  |
| `[^qt^]` и др.             | Статистика: время, число запросов                     |

## API для сниппетов (`$modx`)

`getDocumentChildren()` (`:3901`), `getDocuments()` (`:3966`), `getChildIds()` (`:3168`), `makeUrl()`
(`:4260`), `getChunk()` (`:4481`), `parseChunk()` (`:4603`), `parseText()` (`:4524`), `runSnippet()` (`:4449`),
`getTemplateVar()` (`:4903`), `invokeEvent()` (`:5621`), `sendErrorPage()` (`:411`), `sendRedirect()` (`:326`).
На практике сайты строят на поставляемых сниппетах **DocLister** (списки и меню) и **FormLister** (формы).

## Отложенная публикация и ссылки

- `updatePubStatus()` (`:1157`) работает в начале запроса. Если наступило запомненное время ближайшего
  изменения, Evo публикует документы с `pub_date <= now` и снимает с `unpub_date <= now`, вызывает
  `OnDocPublished` / `OnDocUnPublished` и сбрасывает весь кэш. Сами `pub_date` / `unpub_date` при этом не
  очищаются. CMS очищает сработавший момент, чтобы ручное снятие не отменялось.
- Weblink (`type = 'reference'`) отдаёт 301 на `content` документа (`_sendRedirectForRefPage()`, `:3088`).
  Если там голый id, он сначала превращается в URL документа.

## TV

Значение TV может быть @-привязкой (`app/includes/tmplvars.commands.inc.php`, `:7`): `@FILE`, `@CHUNK`,
`@DOCUMENT`, `@SELECT`, `@EVAL`, `@INHERIT`, `@DIRECTORY`. Чаще всего нужен `@INHERIT` (взять значение у
предка). Остальные привязки — логика, спрятанная в данных. Виджеты вывода — `tmplvars.format.inc.php`.

## События

В `system_eventnames` 145 событий. Основные группы:

- **рендер:** `OnLoadWebDocument`, `OnParseDocument`, `OnWebPagePrerender`, `OnWebPageComplete`,
  `OnPageNotFound`, `OnPageUnauthorized`, `OnMakeDocUrl`, `OnStripAlias`;
- **кэш:** `OnMakePageCacheKey`, `OnLoadWebPageCache`, `OnBeforeSaveWebPageCache`, `OnCacheUpdate`,
  `OnSiteRefresh`;
- **формы менеджера:** `OnBefore…FormSave`, `On…FormSave`, `On…FormDelete`, `On…FormRender` для каждого типа
  элемента и документа;
- **вход и пользователи:** `OnManagerLogin`, `OnWebLogin`, `OnManagerAuthentication`…;
- **интерфейс менеджера и файловый менеджер:** `OnManagerTreeRender`, `OnFileBrowserUpload`…

Плагины одновременно и **слушают** события, и **меняют** данные: через `$modx->documentOutput` и параметры
события.

## Поставка

- Сниппеты: DocLister, FormLister, if, summary, docinfo, phpthumb.
- Плагины: TinyMCE4, CodeMirror, ManagerManager (настройка форм), TransAlias (алиас из заголовка),
  QuickManager (правка с фронта), ElementsInTree, FileSource, updater.
- Модули: DocManager, Store.

## Что берём, что меняем, что выбрасываем

| Evo                                | CMS                                                                                                    | Почему                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| Дерево ресурсов                    | **Берём:** дерево страниц, алиасы, путь из алиасов, меню-индекс, скрытие из меню, публикация           | Это центр модели                                 |
| Шаблон на ресурс                   | **Берём:** у страницы один шаблон                                                                      | Просто и понятно                                 |
| TV, назначаемые на шаблоны         | **Берём** как поля, с наследованием вместо `@INHERIT`                                                  | Гибкая модель без миграций схемы                 |
| Кэш HTML + `[!…!]`                 | **Берём** двухфазный рендер: кэшируемая страница и некэшируемые регионы                                | Главный источник скорости                        |
| Правка элементов в браузере        | **Берём:** компиляция при сохранении                                                                   | Главный источник удобства                        |
| Теги и многопроходный парсер       | **Меняем** на дерево Svelte-компонентов, рендер за один проход                                         | Типы, scoped CSS, никаких повторных проходов     |
| Чанки и сниппеты                   | **Меняем** на компоненты ([ADR 0005](adr/0005-components-instead-of-chunks-and-snippets.md))           | В Svelte разница между ними стирается            |
| PHP `eval`                         | **Меняем** на компиляцию Svelte с белым списком импортов                                               | Предсказуемо, без доступа к ФС и сети            |
| Полный сброс кэша при сохранении   | Пока **так же**, затем точная инвалидация по графу зависимостей                                        | Граф импортов уже известен                       |
| MySQL                              | **Меняем** на SQLite                                                                                   | Один файл, синхронный быстрый доступ             |
| Плагины на 145 событий             | **Меняем** на небольшой набор хуков на TS и доменные события                                           | Меньше, но с понятным контрактом                 |
| `@EVAL`, `@SELECT` и др.           | **Выбрасываем**                                                                                        | Логика живёт в компонентах, а не в данных        |
| Суффикс `.html`, обходы для IIS    | **Выбрасываем**                                                                                        | Чистые URL без суффикса, один канонический адрес |
| `contentType` и пустой шаблон      | **Берём:** тип у страницы, не-HTML — страница-файл без шаблона ([ADR 0017](adr/0017-content-types.md)) | Ленты, robots.txt, стили правятся в менеджере    |
| Отдельные manager/web пользователи | **Меняем** на единых пользователей с ролями                                                            | Проще модель доступа                             |
